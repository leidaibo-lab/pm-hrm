## 一、字段级定义（当前优先）

字段定义属于P0，对应功能技术设计前必须明确。可按依赖逐批收口，不要求全部模块一起等待。下列对象组是字段梳理范围，不代表新增独立业务模块。

- [ ] **F-01 人员与组织基础**：定义人员身份、姓名、邮箱、部门及必要关系；核实人员范围、唯一识别、同名与邮箱变更、是否需要人员状态及管理动作。对应WP-01／R-15。字段规则未明确前不交接相关身份功能。
- [ ] **F-02 账号、角色与责任指派**：定义人员账号关联、角色绑定、账号状态；明确职位HR负责人、用人负责人及场次参与／完成责任人的关系、资格、变更与历史。一人账号数量等建议先确认；通用规则归公共规范，平台承载管理交互，招聘维护业务指派。
- [ ] **F-03 招聘职位**：逐项复核名称、部门、招聘人数、负责人、类型、地点、飞书来源链接、发布时间与状态；区分人工录入和系统产生字段。对应US-101／102。
- [ ] **F-04 候选人、简历与来源**：定义应聘记录身份、联系方式、职位关联、渠道、来源标识、导入信息、简历版本、合并及历史关联。明确外部来源证据可取得形式和缺失处理。对应WP-02／R-10、US-201至203。
- [ ] **F-05 筛选与邀约**：定义筛选结论、备注、责任和操作时间；定义邀约状态、结果、备注及允许更正的条件。引用D-020准入，不重开双活动流程合并要求。对应US-301／302。
- [ ] **F-06 流程模板与面试场次**：定义岗位分类、职级、轮次及完整快照；明确计划开始／结束或时长、会议链接、实际参与人、完成责任人、实际完成时间、取消／未到场和替代关联。输入、默认、必填、改期与更正边界明确。对应WP-03／R-11、US-401／402。
- [ ] **F-07 评价与招聘决策**：整理结构化评价、结论、附件、建议职级、作者及版本；定义决策结果、原因、实际操作人和时间，区分引用事实与独立输入，不新增录用门槛。对应US-403／404、D-019／021。
- [ ] **F-08 待办、消息、字典及审计**：定义产品可见的任务来源、责任、期限／逾期标识、消息收件人和已读信息、字典选项及审计查询字段；区分业务完成与已读。审计共性字段只在公共规范维护。对应WP-04／R-12、13和US-501／502／601／602。

### 每组字段的完成标准

- [ ] 有完整字段清单：字段名称、业务含义、用途、业务数据类型／多值性、来源／生成方式、默认值、必填条件、选项或关联对象及公共格式引用。
- [ ] 明确业务校验与字段关系：不同状态／动作下的条件、可修改性、失败提示及修改影响；不能用“时间”“来源标识”等名称代替定义。
- [ ] 明确查看、修改、下载／导出边界及敏感性；历史、版本、删除／恢复和保留规则按适用对象说明或引用。
- [ ] 建立字段→页面／动作→故事→验收的关联，准备正常、缺失、非法、权限及适用状态的验证样例。
- [ ] 已确认字段与待决策项分开标记；已确认规则回写公共规范／平台／模块权威位置，图示及追踪同步。
- [ ] 对应功能交接前不存在会改变输入、准入或权限的未决字段；产品、研发、测试可从同一份定义得出相同预期。

上述清单是产品字段字典，不提前确定数据库列名、索引、存储类型或接口契约。模块业务字段可在模块PRD关联独立字段清单；平台能力字段归平台目录，共性校验仅引用公共规范。
