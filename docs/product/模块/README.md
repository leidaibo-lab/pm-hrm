# 业务模块需求结构

本目录保存业务模块需求。系统目标、全局架构与能力依赖由[系统总PRD](../产品总览.md)维护；共性规则由公共规范维护；平台能力在平台目录维护。当前独立业务模块为[招聘管理](招聘管理/README.md)。

## 标准阅读结构

每个模块PRD应覆盖以下十一项。现有文档可以提供明确章节索引，不要求为统一编号搬动已确认规则；新增模块按项目要求建立README、范围说明、PRD和用户故事。

| 章节 | 必须能回答的问题 | 维护要求 |
| --- | --- | --- |
| 1. 目标、用户与成功指标 | 为谁解决什么问题，业务价值如何验证？ | 引用系统目标和指标口径，说明模块价值 |
| 2. 范围与依赖 | 本期做什么，外部系统和平台承担什么？ | 链接范围说明、决策与公共规范 |
| 3. 角色、权限与责任 | 谁对哪些记录可执行什么操作？ | 模块矩阵明确数据范围、指派与状态条件 |
| 4. 业务对象与字段字典 | 数据含义、来源、必填、关系、修改和历史如何处理？ | 字段按TODO完成标准定义；共性校验只引用 |
| 5. 主流程与状态 | 谁交接给谁，什么事实触发下一步？ | 链接流程图、状态图，明确人工与自动动作 |
| 6. 功能需求 | 每项功能入口、输入、前置、动作、输出是什么？ | 不用页面名称代替业务规则 |
| 7. 页面与交互 | 用户如何操作，成功、失败、等待、拒绝如何反馈？ | 复杂交互给文字结构或原型，标明尚缺部分 |
| 8. 非常规与异常 | 取消、替代、变更、迟交、并发和终止如何处理？ | 只定义适用情况，关联决策与场景 |
| 9. 治理与公共规则差异 | 敏感访问、历史、删除、恢复和保留如何控制？ | 只写模块差异，不重复公共机制 |
| 10. 验收与追踪 | 如何独立验证，证据在哪里？ | 链接故事、场景、追踪及真实执行结果 |
| 11. 未决项与交付 | 哪项政策未确认，影响哪些功能，下一步是什么？ | 推荐方案与确认结论分开，说明局部依赖 |

## 字段和交接要求

字段定义在对应功能技术设计前收口，执行顺序及标准见[TODO](../TODO.md)。文档结构覆盖、字段规则明确、实现验证通过和产品效果达标分别判断；字段清单有标题但内容不完整时，不能标记已完成。
