# 招聘管理业务流程与数据流转图

- **日期**：2026-10-10。
- **用途**：研发、测试与产品共同理解业务输入输出、角色交接及正常／非常规链路。
- **范围**：现有招聘 MVP 的图示表达，依据[产品决策 D-001 至 D-021](../../产品探索/产品决策记录.md)，重点采用 D-018、D-019、D-020、D-021 的最新口径，不新增业务功能。
- **权威依据**：[范围说明](范围说明.md)、[PRD](产品需求文档.md)、[面试流程与评价最小配置](面试流程与评价最小配置.md)。公共校验、授权、审计与生命周期分别引用[字段规范](../../公共规范/字段与表单校验规范.md)和[权限与数据治理规范](../../公共规范/权限与数据治理规范.md)。
- **阅读方式**：先看系统级[业务架构与全局数据流](../../产品总览.md)，再读本文件的数据流、对象关系、泳道和状态，最后对照异常子图与验收索引。

图中的箭头表示业务数据传递或条件成立后的动作。角色泳道表示责任交接，不替代 PRD G.1 授权判断。业务对象表示需求概念，不定义数据库表、接口或存储结构。成功指标引用[指标与试点基线](../../指标与试点基线.md)，验收引用现有[测试场景](../../验收与追踪/招聘管理测试场景.md)，本文件不另设指标口径。

## 一、模块数据流转

```mermaid
flowchart LR
    SourceJob["飞书已发布职位信息"]
    SourceCV["Boss直聘简历与来源信息"]
    Job["HR人工建档<br/>职位、部门、HR负责人、用人负责人"]
    Candidate["HR人工导入<br/>同职位应聘记录、简历版本、来源追溯"]
    Screening["HR推荐及用人负责人初筛<br/>结果、备注、阶段历史"]
    Invite["HR记录外部邀约<br/>答复状态、备注"]
    Template["按职位、岗位分类及职级配置的流程模板"]
    Snapshot["首次安排的完整流程快照"]
    Session["具体面试场次<br/>轮次、人员、时间、完成责任与结果"]
    Evaluation["逐场次逐人评价<br/>结论、七项文字维度、建议职级及版本"]
    Gate["系统判断推进或终止<br/>当前阶段、有效评价、完成及责任清单"]
    Decision["招聘结果<br/>HR沟通记录及录用／淘汰／放弃"]
    Platform["平台工作台与站内通知"]
    History["审计与历史证据"]
    SourceJob -->|HR登记职位及来源关联| Job
    SourceCV -->|HR导入资料| Candidate
    Job -->|职位归属与可招聘准入| Candidate
    Candidate -->|资料及当前阶段| Screening
    Screening -->|初筛推荐且D-020检查通过后进入待邀约| Invite
    Template -->|首次安排时选定并保存| Snapshot
    Invite -->|同意后HR创建面试| Session
    Snapshot -->|本轮配置及评价模板| Session
    Session -->|场次、轮次、实际评价责任| Evaluation
    Session -->|实际完成或合法跳过事件| Gate
    Evaluation -->|有效结论及责任提交情况| Gate
    Gate -->|非终面满足通过条件或合法跳过：下一轮待安排| Session
    Gate -->|最终实际轮完成、评价齐全且通过：待决策| Decision
    Gate -->|任一有效不通过：淘汰| Decision
    Gate -->|待安排、缺评价、待决策或停止任务| Platform
    Candidate -->|导入、资料变更与合并关系| History
    Session -->|原场次、替代关系、指派及配置变更| History
    Evaluation -->|原作者、内容与修改版本| History
    Decision -->|操作者、时间、原因及状态变化| History
```

最终实际轮通常为配置终面；负责人确认 CTO不参与时，按第六节引用前一有效实际轮承接最终评价。图中“下一轮待安排”不等于自动创建面试场次。建议职级只作为评价信息，不改变原流程快照。手动淘汰／放弃仍按当前阶段责任人授权，录用由 HR在待决策完成外部确认后二次确认。

## 二、业务对象关系

```mermaid
flowchart TB
    Job["职位"]
    Candidate["候选人应聘记录<br/>每条记录只关联一个职位"]
    Resume["简历及附件版本"]
    Flow["候选人完整流程快照及变更快照"]
    Round["业务轮次<br/>保留原名称和顺序"]
    Session["实际面试场次<br/>同轮可有取消及替代场次"]
    Assignment["实际参与人及有效评价责任清单<br/>终面另指定一名完成责任人"]
    Eval["每场次每位实际评价人的独立评价"]
    Version["评价修改版本<br/>保留原作者"]
    Merge["同职位主记录与旧记录的合并关系"]
    HREvent["HR沟通及招聘决策记录"]
    Job -->|一个职位可有多条| Candidate
    Candidate -->|保留多个版本及当前选择| Resume
    Candidate -->|首次安排保存| Flow
    Flow -->|包含多个| Round
    Round -->|关联具体| Session
    Session -->|记录指派及交接| Assignment
    Assignment -->|按独立责任提交| Eval
    Eval -->|保留修改前后内容| Version
    Session -->|新替代场次关联原场次| Session
    Candidate -->|合并不销毁旧证据| Merge
    Candidate -->|关联处理结果| HREvent
```

同一人在不同职位分别建立应聘记录和流程，不跨职位合并。可选面试官名单属于配置，实际参与人属于具体场次；名单不自动授予访问权。同场换人的评价复用与新替代场次的重新评价见第五节。历史证据的保存不意味着原参与人持续拥有访问权，当前授权按 PRD G.1 判定。

## 三、正常业务协作泳道

```mermaid
flowchart TB
    subgraph HRLane["HR成员"]
        H1["飞书发布后建档，导入Boss简历"]
        H2["检查资料并推荐"]
        H3["外部邀约并记录同意"]
        H4["按快照安排本轮人员与时间"]
        H5["记录HR沟通，外部确认可入职后二次确认录用"]
    end
    subgraph OwnerLane["当前职位用人负责人"]
        O1["初筛推荐"]
        O2["维护职级流程与轮次人员指派"]
    end
    subgraph InterviewLane["当前实际面试官"]
        I1["实际面试并分别提交本人评价"]
        I2["非终面当前参与人结束本轮<br/>终面由指定完成责任人结束"]
    end
    subgraph SystemLane["HRM系统"]
        S1["校验账号、完整授权、当前状态与公共字段"]
        S2["判断本轮完成及有效评价"]
        S3["非终面通过：定位下一轮并生成待安排事项"]
        S4["最终实际轮完成且评价齐全通过：自动待决策并激活HR沟通"]
    end
    H1 --> H2 --> O1 --> Duplicate{"D-020：同职位已有强匹配活动流程？"}
    Duplicate -->|是| Denied["拒绝推荐，保持初筛，提示原流程阶段"]
    Duplicate -->|否| H3 --> S1 --> H4
    O2 -->|提供流程及指派上下文| H4
    H4 --> I1 --> I2 --> S2
    S2 -->|非终面满足通过条件| S3 --> H4
    S2 -->|最终实际轮满足门槛| S4 --> H5
```

本图只展示通过路径，评价与结束动作可分别发生，系统在相关事实变化后重新判断门槛；异常、不通过、缺交及跳轮见后续图。所有泳道动作均受 PRD G.1 约束。H4不能从未来未开始轮提前提交评价或结束；终面评价提交不替代完成责任人的结束动作。

## 四、候选人阶段与独立状态

### 4.1 候选人阶段

```mermaid
stateDiagram-v2
    state "待筛选" as Screening
    state "初筛" as Initial
    state "待邀约" as Invitation
    state "面试中" as Interviewing
    state "待决策" as Deciding
    state "录用" as Hired
    state "淘汰" as Rejected
    state "候选人放弃" as Withdrawn
    [*] --> Screening
    Screening --> Initial: HR检查并推荐
    Initial --> Initial: 待补充或D-020重复流程拦截
    Initial --> Invitation: 初筛推荐且D-020检查无重复活动流程
    Invitation --> Interviewing: 邀约同意且HR创建面试
    Interviewing --> Deciding: 最终实际轮完成、有效责任评价齐全且通过
    Deciding --> Hired: HR外部确认后二次确认
    Screening --> Rejected: HR主动淘汰
    Initial --> Rejected: 用人负责人初筛不通过
    Invitation --> Rejected: HR主动淘汰
    Interviewing --> Rejected: 任一轮有效不通过或授权责任人主动淘汰
    Deciding --> Rejected: 有效迟交不通过或授权责任人主动淘汰
    Screening --> Withdrawn: 当前环节授权责任人主动操作
    Initial --> Withdrawn: 当前环节授权责任人主动操作
    Invitation --> Withdrawn: 当前环节授权责任人主动操作
    Interviewing --> Withdrawn: 当前环节授权责任人主动操作
    Deciding --> Withdrawn: 当前环节授权责任人主动操作
    Hired --> [*]
    Rejected --> [*]
    Withdrawn --> [*]
```

终止状态不回退；修改历史评价、恢复软删除或重开职位不恢复终止流程。阶段动作的逐项角色以 PRD D、G.1 为准。

### 4.2 邀约、轮次、场次分别表达

| 状态维度 | 取值／节点 | 对候选人阶段的影响 |
| --- | --- | --- |
| 邀约 | 待邀约、邀约中、同意、拒绝、失联 | 同意是创建面试前置条件；拒绝／失联不自动放弃或淘汰 |
| 业务轮次 | 未开始、待面试、已结束待评价、评价已齐、已跳过 | 完成、评价及跳过按第五／六节决定是否推进，不凭节点名称直接改阶段 |
| 面试场次 | 待面试、已完成、公司取消、候选人取消、未到场 | 取消／未到场保留场次结果，可创建同轮替代场次，不自动终止候选人 |

邀约只表达已确认结果及准入条件，现有决策没有定义全部结果之间的转换矩阵，本文件不自行补画任意回退或重新邀约箭头。若后续建设邀约重开交互，需要先补充决策和验收。

## 五、非常规面试链路

### 5.1 评价不通过、待定、缺交与通过门槛

```mermaid
flowchart TB
    Event["实际完成、评价提交或有效评价变更"] --> Active{"候选人仍为非终止状态？"}
    Active -->|否| Keep["保留原终止结果，不自动恢复"]
    Active -->|是| Fail{"任一轮存在有效不通过？<br/>包含前轮迟交"}
    Fail -->|是| Reject["自动淘汰<br/>停止后续面试及相关待办、提醒"]
    Fail -->|否| Current{"当前实际轮已结束<br/>且有通过反馈、无待定？"}
    Current -->|否| Wait["保持当前节点<br/>待定由当前职位负责人按权限补充修改<br/>保留评价版本及缺交责任"]
    Current -->|是| Final{"是否承接最终评价的实际轮？"}
    Final -->|否| Next["定位下一业务轮、通知HR待安排<br/>前轮缺交待办仍保留"]
    Final -->|是| Full{"实际完成责任有效<br/>有效评价责任清单齐全？"}
    Full -->|否| Missing["保持面试中<br/>向当前缺交责任人生成站内待评价消息"]
    Missing -->|补交或责任变更后重新判断| Event
    Full -->|是| Decision["自动进入待决策、激活HR沟通<br/>缺交消息停止，开始待决策提醒计时"]
```

此图适用于实际面试，合法跳过走下一子图。终面缺交消息频率见最小配置第6节；进入待决策后的长期未推进提醒按 PRD F 执行，两类提醒分别验收。评价通过不自动录用，HR沟通结果不额外阻断进入待决策。

### 5.1.1 前轮迟交待定

```mermaid
flowchart TB
    Late["有效评价为待定"] --> Position{"评价所属轮是否仍为当前实际轮<br/>或承接最终评价的实际轮？"}
    Position -->|是| Hold["保持该节点，负责人补充修改<br/>通过后再按D-019判断"]
    Position -->|否：已合法进入后轮| Continue["D-021：不回退、不取消场次<br/>不暂停后轮，不新增录用门槛"]
    Continue --> Evidence["详情保留前轮待定及作者版本<br/>当前职位负责人待处理项"]
    Evidence --> Amend["负责人按原权限补充修改<br/>保留依据及版本"]
    Amend --> Failure{"更新为有效不通过？"}
    Failure -->|是且尚未终止| RejectLate["D-019：自动淘汰并停止任务"]
    Failure -->|否或已终止| Keep["保留当前阶段／既有终止结果<br/>不自动恢复"]
```

该分支依据D-021、PRD E.5及TS-LATE-021；不把前轮待定显示为已通过。终止后停止活动待办，历史证据保留，不新增终止后补交权。

### 5.2 一面跳过与非终面合法跳过

```mermaid
flowchart TB
    Need["排期冲突／多候选人到达等已确认跳轮场景"] --> Auth{"当前实际指派面试官<br/>且轮次允许跳过？"}
    Auth -->|否：未指派、终面或CTO普通跳轮| Deny["拒绝操作<br/>CTO不参与仅走负责人专属例外"]
    Auth -->|是| Evidence{"本轮未实际完成且未提交评价？"}
    Evidence -->|否| Preserve["保留已发生事实，不改为未发生的跳过"]
    Evidence -->|是| Skip["填写原因，保留原节点、操作者及时间<br/>标记已跳过，不伪造评价或缺交任务"]
    Skip --> Next["定位下一业务轮，保留原轮次名称和顺序"]
    Next --> Arrange["HR安排下一轮实际场次<br/>实际人员完成并提交该轮评价"]
```

一面直接从二面开始的人员指派及无人兜底仍受 D-016、D-018 限制，不因“直接开始”免除授权。各职级实际终面定义见 PRD E.1，CTO不参与另见第六节。

### 5.3 取消／未到场后的替代场次与同场换人

```mermaid
flowchart TB
    Change["面试发生变更"] --> Type{"变更类别"}
    Type -->|改期| Reschedule["HR更新时间并保留变更历史<br/>不做飞书日历同步"]
    Type -->|公司取消、候选人取消、未到场| Original["HR记录原场次结果与原因<br/>候选人不自动放弃"]
    Original --> Choice{"有权限的责任人选择后续动作"}
    Choice -->|继续安排| Replacement["HR基于原邀约创建同轮新场次<br/>关联原场次，不重新邀约"]
    Replacement --> NewEval["新实际指派、实际完成、重新评价<br/>旧场次评价不能满足新场次门槛"]
    Choice -->|主动放弃| Withdraw["按当前环节授权记录原因并终止"]
    Type -->|同场次同轮换人| Swap["保存新旧指派与责任交接"]
    Swap --> Submitted["已交责任：保留原评价和作者，不重评"]
    Swap --> Pending["未交责任：转给接任人<br/>新人提交本人评价，不增加双份义务"]
    Submitted --> Gate["按交接后有效责任清单重新判断门槛"]
    Pending --> Gate
```

### 5.4 本轮无人、账号无效与责任交接

```mermaid
flowchart TB
    Empty["当前轮无有效实际人员"] --> Previous{"前面最近实际指派轮<br/>有有效可用人员？"}
    Previous -->|是| Bind["保存本轮兜底指派、来源轮及时间"]
    Previous -->|否| Later{"后面最近实际指派轮<br/>有有效可用人员？"}
    Later -->|是| Bind
    Later -->|否| Block["告警当前职位负责人，待配置<br/>阻止结束、跳过与流转"]
    Bind --> Final{"本轮为最终实际轮？"}
    Final -->|否| Execute["按本轮实际指派执行"]
    Final -->|是| Count{"兜底人员数量"}
    Count -->|一名| Single["由该人承担完成责任"]
    Count -->|多名| Assign["HR或当前职位负责人<br/>明确指定一名完成责任人"]
    Single --> Execute
    Assign --> Execute
```

来源只取有效实际指派，不取可选名单；停用账号、已撤销角色和无效指派不作为来源。负责人不自动成为面试官。职位负责人变更按 PRD G.3、轮次换人按第五节交接；历史操作者不改写，解除指派后的访问按当前授权判断。HR负责人解除及重新指定按 TS-JOB-002 验收，一期不增设账号禁用专属业务流程。

## 六、CTO不参与与最终评价承接

```mermaid
flowchart TB
    Start["CTO无时间参与"] --> Auth{"当前职位用人负责人操作<br/>且CTO尚未实际完成？"}
    Auth -->|否| Deny["拒绝普通跳轮或事后抹除历史"]
    Auth -->|是| Change["填写原因并确认前一有效实际轮<br/>保留CTO原节点、指派及候选人变更快照"]
    Change --> Valid{"存在有效实际前轮<br/>且有明确有效责任人？"}
    Valid -->|否| Block["配置警告并阻止空流转<br/>跳过轮、取消场次及旧替代评价不作承接"]
    Valid -->|是| Ref["引用原场次、轮次、评价人及版本<br/>不复制或伪造CTO评价"]
    Ref --> Failed{"有效评价含不通过？"}
    Failed -->|是| Reject["自动淘汰，停止后续任务"]
    Failed -->|否| Ready{"该实际轮已完成<br/>有效评价清单齐全且通过？"}
    Ready -->|否| Wait["保持面试中，等待完成或补充评价<br/>缺交消息发给承接轮当前责任人"]
    Wait -->|事实变化后重新判断| Failed
    Ready -->|是| Decision["自动待决策并激活HR沟通<br/>不要求未执行CTO评价"]
```

变更只作用于该候选人流程，标准模板和原始快照保留；CTO未执行部分停止待办，不产生重复缺交消息。CTO正常参加则走标准终面完成与评价门槛。进入待决策不等于录用，后续仍由HR完成外部确认及二次确认。

## 七、其他异常入口与验收索引

下表补充跨越多个图示的异常入口。链接指向现有测试文档；编号可在该文档检索，对应 PRD／配置章节为业务规则入口。

| 链路 | 触发、责任动作与数据去向 | 规则依据 | 验收场景 |
