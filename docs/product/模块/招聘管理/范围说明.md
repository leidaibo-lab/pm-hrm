# MVP 范围草案

## MVP 目标

在不改变公司现有飞书招聘流程的前提下，由 HR 人工把飞书中的招聘职位登记到 HRM，建立从“职位建档”到“候选人面试与招聘决策”的可追踪协作闭环。

## 业务边界

### 飞书负责

1. 创建招聘需求
2. 审批招聘需求
3. 发布职位

飞书是这三步的权威来源。HRM 不重复建设审批页面，不保存一套可独立生效的审批结果。飞书 API 同步属于后续优化，不是一期前置条件。

### HRM 负责

1. 由 HR 登记飞书已发布职位，创建 HRM 职位源数据
2. 维护候选人及其招聘阶段
3. 由 HR 从 Boss 直聘获取简历后直接录入 HRM
4. 创建和安排面试
5. 在 HRM 记录面试时间和面试协作信息，一期不与飞书日历同步
6. 通知面试官并收集结构化评价
7. 跟踪招聘进度、阻塞事项和逾期任务
8. 记录录用、淘汰、候选人放弃和职位关闭结果
9. 通过工作台聚合 HR、用人负责人和面试官的待办

## 第一个完整业务闭环

```text
飞书：创建招聘需求 -> 审批 -> 发布职位 -> 关闭 -> 重新打开
                                  |          |          |
                                  |          |          +--> HR 恢复 HRM 可招聘状态
                                  |          +--> HR 调整 HRM 状态，禁止新增候选人
                                  v
HR成员：在 HRM 登记职位 -> 录入候选人 -> 面试 -> 评价 -> 招聘决策
                                  ^
                                  |
                           HRM 记录面试时间
```

## 角色与核心任务

| 角色／责任身份 | MVP 内的核心任务 |
| --- | --- |
| HR成员/招聘专员 | 维护职位、候选人、面试安排和招聘结果；其中 HR负责人对具体职位负责 |
| 用人负责人 | 查看职位候选人、参与面试决策、处理招聘协作待办；作为职位主负责人被指定 |
| 面试官 | 查看分配的面试并提交结构化评价 |
| 系统管理员 | 管理用户、角色、组织范围和审计记录 |

老板在一期主要继续使用飞书完成招聘需求、审批和发布，不要求在 HRM 中完成上述动作。

### HR 术语约定

- **HR成员**：系统业务角色，拥有招聘数据的查看和操作权限。
- **HR负责人**：职位上的主责 HR成员，每个职位配置一名，负责该职位的日常跟进并接收长期未推进提醒。
- HR负责人不是独立于 HR成员之外的新角色；最终录用仍由有权限的 HR成员确认，默认可由 HR负责人执行。
- HR成员或管理员可以解除用户在职位上的 HR负责人绑定并重新指定具备 HR成员角色的负责人；变更只影响后续责任和提醒，不改写历史操作人。
- **职位用人负责人（简称用人负责人）**：从具备面试官角色的用户中按职位指定的责任身份，每个职位一名；不配置独立同名业务角色。负责该职位的初筛、面试官指定和招聘决策，查看范围限定到负责职位。
- **面试官**：系统业务角色，按面试轮次指派具体参与人；不是职位固定字段，可以一次指定多人或临时更换。
- 一个用户可以同时拥有多个业务角色；角色决定权限，职位或面试上的指派决定具体责任范围。

### 角色授权说明

本模块采用[产品决策 D-013](../../产品探索/产品决策记录.md)：职位用人负责人不自动参与各轮面试，提交本人评价须另有本轮面试指派；终面完成仍需终面完成责任面试官指派。

业务角色、操作权限、数据范围、责任指派及状态条件的定义遵循[公共权限规范](../../公共规范/权限与数据治理规范.md)第 3 节。HR负责人是职位责任指派；用人负责人按“面试官角色＋职位负责人指派”判断；面试官角色与本轮面试指派分别判断。岗位分类中的“招聘角色”仅用于模板匹配，不授予业务权限。

本节角色表用于说明职责，不作为全部操作的授权依据。具体操作以[模块 PRD](产品需求文档.md)的 G、G.1 为准；G.3 列出的边界已按 D-016 收口，作为授权实施依据。多角色用户按各角色完整授权合并，不能将全公司查看范围与其他角色的修改权限拼接。

## 一期必须做

### 公共表单校验

所有模块的新增、编辑和提交表单统一遵循[字段与表单校验规范](../../公共规范/字段与表单校验规范.md)，包括必填、首尾空白、字段长度、格式、数值范围、附件、重复提交和服务端校验。字段的具体长度和文件大小按公共规范的 MVP 默认基线执行。

### 职位接入

- 展示职位名称、部门、招聘负责人、用人负责人、招聘人数和来源链接。
- 由 HR 在飞书职位发布完成后手动创建 HRM 职位。
- 记录飞书来源链接、飞书审批/发布状态和 HRM 招聘状态。
- 能识别重复建档和职位信息缺失。
- 一期不要求飞书 API 同步；后续同步不能破坏 HR 在 HRM 中维护的招聘协作数据。

### 职位状态规则

- 飞书审批通过是 HR 可以处理职位的前置事实，但不是 HRM 建档触发点。
- 飞书职位发布后，HR 才能在 HRM 创建职位并开始录入候选人。
- 飞书职位关闭后，HRM 职位保留历史数据，禁止新增候选人；已有候选人的面试、评价、招聘决策和录用不受影响。
- 飞书职位重新打开后，HR 复用原招聘申请和 HRM 职位，手动恢复可招聘状态后才允许新增候选人。

### 职位必填字段

- 职位名称
- 部门
- 招聘人数
- 用人负责人：从具备面试官角色的用户中指定，每个职位一名
- HR 负责人
- 职位类型
- 工作地点
- 飞书审批申请链接
- 发布时间

飞书审批申请链接建议保留为必填来源凭证，用于追溯招聘需求和审批记录；它不是 HRM 审批入口。面试会议链接单独记录在面试信息中，不与职位字段混用。
面试轮次根据招聘角色和面试职级配置，不在职位上固定一套通用轮次。

### 候选人管理

- 候选人列表、搜索、筛选和阶段变更。
- 候选人与职位的关联关系。
- 仅允许 HR 从 Boss 直聘获取简历并上传到 HRM，候选人不直接上传。
- 简历保留 Boss 直聘来源标识、导入时间和导入人，便于追溯来源；一期不再将简历存入飞书云盘。
- Boss 直聘侧授权是 HRM 接收数据前的外部前置事实；HRM 不重复建设、核验或管理授权、告知、撤回和授权状态，HR 只负责将具体招聘数据导入并落地到 HRM。
- 简历或附件访问权限。
- 候选人阶段变更记录和操作人。

候选人一期必填字段：姓名、联系方式、简历、来源渠道、应聘职位。每份应聘记录只关联一个职位；同一人跨职位投递建立独立记录、分别走流程，不跨职位合并。

### 候选人筛选流程（一期规则）

```text
HR 从 Boss 直聘取得简历
        |
        v
待筛选 --HR 推荐--> 初筛 --初筛通过且重复流程检查通过--> 待邀约 --同意--> 面试中 -> 待决策 -> 录用/淘汰/候选人放弃
                                                                      |
                                           公司取消/候选人取消/未到场 --+--> 替代面试或终止
```

- **待筛选**：HR 已将候选人和简历录入 HRM，负责资料完整性检查和是否推荐给用人负责人的前置判断。
- **初筛**：用人负责人已收到 HR 推荐，候选人等待初步判断；用人负责人需要记录通过、不通过或待补充结果和备注。
- “HR 推荐”是从待筛选进入初筛的动作，不单独增加复杂阶段。
- 用人负责人初筛通过且通过D-020重复活动流程检查后，候选人才能进入“待邀约”；不通过的候选人进入淘汰，待补充的候选人继续停留在“初筛”，两者都不能直接创建面试。
- 初筛通过且无同职位强匹配活动流程时进入“待邀约”，由 HR 联系候选人并记录邀约状态。
- 候选人同意赴约后，HR 才能创建面试；用人负责人再指定面试官。

HRM 一期不直接向候选人发送外部消息。“发送邀约记录”表示 HR 在 HRM 中记录已通过 Boss 直聘等招聘平台完成邀约，以及候选人的答复结果。

### 候选人阶段与变更责任

| 当前阶段 | 允许的下一阶段 | 可执行角色／责任身份 | 进入条件 |
| --- | --- | --- | --- |
| 待筛选 | 初筛、淘汰、候选人放弃 | HR | HR 完成资料检查并推荐，或记录终止原因 |
| 初筛 | 待邀约、淘汰、候选人放弃 | 用人负责人；HR 可记录候选人放弃 | 用人负责人完成初筛并记录推荐、不推荐或待补充结果 |
| 待邀约 | 面试中、淘汰、候选人放弃 | HR | 候选人同意赴约后创建面试；拒绝或失联时由当前邀约环节责任人员主动终止 |
| 面试中 | 待决策、淘汰、候选人放弃 | 用人负责人、面试官、HR | 终面面试官点击完成面试，且该轮有效评价责任清单齐全且通过时自动待决策；任一有效面试评价不通过自动淘汰，或当前环节责任人员主动记录终止原因 |
| 待决策 | 录用、淘汰、候选人放弃 | HR、用人负责人、面试官；录用仅 HR | HR 与候选人在 Boss 直聘确认可入职后，HR 二次确认录用 |
| 录用 | 无 | HR | 终止状态 |
| 淘汰 | 无 | 当前招聘环节责任人员 | 终止状态，不允许恢复 |
| 候选人放弃 | 无 | 当前招聘环节责任人员 | 终止状态，不允许恢复 |

候选人状态不允许退回上一个阶段。淘汰和候选人放弃不允许恢复；同一阶段有多个可操作角色时，系统必须记录操作人、时间和变更前后状态。

邀约状态调整为：待邀约、邀约中、同意、拒绝、失联。候选人是否同意以招聘平台上的答复为准；邀约状态变更时必须填写备注。候选人拒绝或失联时，当前邀约环节责任人员可将候选人状态置为候选人放弃。

### 面试协作

按[决策 D-019](../../产品探索/产品决策记录.md)及[PRD E.4](产品需求文档.md)：实际业务轮结束、有通过反馈且无不通过／待定才继续，非终面缺交保留待办；任一轮有效评价不通过直接淘汰并停止后续面试，不补终面。待定保持当前节点，经当前职位负责人依据补充材料修改有效评价版本后再判断。CTO不参与仅由当前职位负责人对具体候选人确认，引用前一有效实际轮评价；承接轮须实际完成、有有效责任人、评价清单齐全且通过，无前轮则告警，缺评则提醒并等待。替代场次为新实际面试，必须重新评价；同场次同轮换人复用已交评价。职级差异仅在评价体现，不改安排及流程。



- HR 创建面试，用人负责人指定面试官；邀约状态不是“同意”时不能创建面试。
- 面试时间直接记录在 HRM，按招聘角色和面试职级使用对应轮次配置；一期不与飞书日历同步。
- 面试官待办和逾期提示。
- 结构化面试评价、结论和提交时间。
- 面试状态和结果：待面试、已完成、公司取消、候选人取消、未到场；终面面试官点击“完成面试”确认实际完成。面试完成后，HR成员或该场面试负责人可修改非评价面试结果。
- 最后一轮可以指定多名面试官，但必须指定一名终面完成责任面试官；只有该面试官可以点击“完成面试”，并作为该场终面负责人维护完成后的面试结果。
- 面试评价至少包含：面试结论、七项文字评价维度（基础能力、项目经验、技术栈、工程化、沟通能力、契合度、AI实践能力）、是否推荐、风险项和文字补充。
- 评价本人不提供修改权限；职位用人负责人可在权限范围内修改所属职位的评价，修改必须记录审计。
- 面试改期直接更新 HRM 面试时间；面试官临时更换直接更新面试官人选。

公司取消面试时，保留候选人面试中状态并记录公司取消原因；HR 可以基于原邀约创建同一轮次的替代面试，不重新发起邀约。候选人取消或未到场时，分别记录原因和备注，也可以创建同一轮次的替代面试。公司取消、候选人取消、未到场、拒绝和失联都可以作为“候选人放弃”的原因；当前招聘环节责任人员都可以主动点击按钮变更，不设置自动时限。面试官临时更换只修改面试官，不改变候选人阶段。

### 面试轮次配置

依据[产品决策 D-015](../../产品探索/产品决策记录.md)，一面人员无时间或多候选人同时到达时，可从二面直接开始。P2／P3-1 由主面试官直接面试反馈后进入 HR沟通，其他职级类推，高级职级标准路径保留 CTO面，负责人确认不参与的例外按 D-019 执行。原一面标记已跳过并记录原因，不伪造评价，已完成一面不能事后跳过；具体路径见 PRD E.3。

按[产品决策 D-014](../../产品探索/产品决策记录.md)及[PRD E.1、E.2](产品需求文档.md)配置：不同职级对应不同业务轮次与人员，各实际场次按轮次、被指派面试官分别保存评价，多轮评价不互相覆盖。HR沟通计入流程环节但只记录沟通结果；终面是最后一轮业务面试。进入待决策要求最终实际业务轮完成及有效评价责任清单齐全且通过（CTO不参与按 D-019 承接），前轮缺交仍保留待办，不新增为阻断条件。

- 面试模板由职位用人负责人维护负责职位、HR维护全公司职位，并按招聘角色和面试职级关联。
- 每一轮的最小配置包括：轮次名称和顺序、面试角色/职级、默认面试时长、评价模板和是否必经。
- 单个职位可以调整轮次，变更需记录操作人和时间，但不能移除职级必经环节；P4及以上标准流程含四环节，按 D-015 可跳过一面，普通面试官不得跳过 CTO面；负责人可按 D-019 确认 CTO不参与。
- 没有匹配模板时，由用人负责人新建模板或补充配置后才能安排面试。
- 面试官可以一次性指定，也可以在具体轮次临时指定；临时指定用于处理面试官时间冲突。

### 招聘工作台

- HR成员：全局招聘、待处理评价和逾期面试；职位 HR负责人负责跟进该职位的长期未推进候选人。
- 用人负责人：自己的职位、候选人、待确认状态和待决策事项。
- 面试官：分配给自己的面试、待评价事项和评价历史。
- 所有角色都可查看与自己权限范围相关的职位和候选人概览。
- 所有提醒一期只在 HRM 内产生，不发送飞书消息。
- 工作台待办支持直接进入候选人详情、记录邀约结果、安排面试、补交面试评价和处理逾期事项；具体动作仍受角色权限和状态前置条件限制。

## 一期暂不做

- HRM 内创建招聘需求。
- HRM 内审批招聘需求。
- HRM 内发布职位。
- 自建通用审批流引擎。
- 飞书 API 自动同步职位和状态。
- 飞书日历同步和飞书消息通知。
- Boss 直聘自动获取或 API 同步简历。
- 历史职位、候选人和面试数据迁移；当前没有历史数据。
- 薪酬、入职、考勤和员工档案全量管理。
- 复杂的招聘网站自动发布。
- AI 自动筛选或自动做录用决策。
- 绩效管理正式流程。绩效保留为招聘闭环验证后的下一阶段。

## 关键验收标准

- HRM 中的每个职位都能追溯到飞书来源、对应业务负责人和登记 HR。
- HR 只能在飞书职位发布完成后手动创建 HRM 职位。
- 候选人只能关联到 HRM 中已创建的职位，且只能由 HR 录入。
- 职位必须包含职位名称、部门、招聘人数、用人负责人、HR 负责人、职位类型、工作地点、飞书审批申请链接和发布时间。
- 候选人必须包含姓名、联系方式、简历、来源渠道和应聘职位；每份应聘记录仅关联一个职位，同一人跨职位建立独立记录和流程，不跨职位合并。
- 职位类型、工作地点、招聘角色、面试职级、候选人来源渠道、面试结论、风险项、淘汰原因和候选人放弃原因均采用可维护字典。
- HR 可以将 Boss 直聘中的简历直接人工导入 HRM，且候选人记录能追溯来源、导入人和导入时间。
- 候选人至少支持“待筛选”和“初筛”两个阶段；HR 负责推荐动作，用人负责人负责初筛结果。
- 管理员创建的用户首次登录必须修改临时初始密码；管理员重置密码后，用户下次登录也必须修改密码，相关操作可追溯到审计记录。
- 各阶段只能由对应责任角色变更；录用必须由 HR 最终确认。
- 用人负责人初筛通过后，候选人必须先记录为“同意”赴约，HR 才能创建面试，用人负责人才能指定面试官。
- 没有完成过任何一轮面试的候选人不进入长期未推进提醒；公司取消面试时可以基于原邀约创建同一轮次的替代面试，不重新发起邀约。
- 候选人导入时按标准化后的姓名和联系方式识别重复：完全一致为强重复，仅姓名相同不判重，联系方式相同但姓名不同提示 HR 判断；缺少联系方式不能录入。
- 仅同职位判重，未面试时先判重不应用期限，实际面试结束后以最近一次实际结束时间起算一年；HR 确认即可合并，但不得覆盖或销毁旧简历、面试安排、面试评价和状态历史，必须保留主记录、历史证据、合并关系和合并审计。
- 飞书职位关闭后，HRM 禁止新增候选人，但已有候选人可以继续面试、进入待决策并录用。
- 飞书职位重新打开后，HR 可以复用原职位恢复候选人录入，不需要重新发起审批。
- 候选人阶段、面试安排和评价状态可由授权角色查看；同部门、同职位的面试官可以查看其他面试评价，但不能修改或冒用他人评价，评价本人也不提供修改权限。
- 用人负责人和面试官可以查看其职位范围内的完整简历；同部门、同职位的面试官可以查看其他面试官的评价。
- 面试时间直接以 HRM 记录为准，一期不做飞书日历同步。
- 面试评价提交后不能无痕修改；同部门、同职位面试官可以查看其他评价，职位用人负责人可在权限范围内修改评价，修改权限与面试结果字段权限独立控制。
- 正常路径终面面试官点击“完成面试”且有效评价责任清单齐全并通过（CTO不参与按 D-019 承接）后，候选人才能进入待决策。
- HR 与候选人在 Boss 直聘确认可入职后，HR 才能在 HRM 点击“录用”；录用不代表 Offer 或已入职。
- 一期暂不设置候选人和简历过期时间，不自动清理；后续制度变化时再补充生命周期规则。
- Boss 直聘授权由平台侧负责并作为外部前置事实；HRM 只记录来源渠道、来源标识、导入人、导入时间和招聘目的等追溯信息，不新增授权状态、告知时间、告知方式或撤回结果字段。
- 招聘负责人能从工作台识别逾期面试评价和阻塞候选人。
- 飞书职位关闭后，HR 可以手动调整 HRM 展示状态；已有候选人流程不被自动删除或强制终止，新增候选人会被阻止。

## 规则补充

- 候选人状态按正向流程推进，不允许退回；淘汰和候选人放弃不可恢复。
- 候选人放弃是当前招聘环节责任人员主动点击产生的终止状态，不设置自动时限；公司取消、候选人取消、未到场、拒绝和失联均可作为放弃原因。
- 多轮面试以当前配置的最后一轮结束作为进入待决策的条件。
- 长期未推进提醒从最后一轮面试完成且该轮有效评价责任清单齐全且通过、候选人进入待决策后开始计算，每 3 个工作日提醒职位 HR负责人和用人负责人；候选人进入待决策后仍继续提醒，同一候选人每天最多提醒一次，状态操作不重置提醒计算。其他 HR成员可从全局工作台查看。
- 工作日按东八区计算，暂不升级给部门负责人。

## 首批试点

- **范围**：技术部前端招聘。
- **目标**：验证 HR 建档和简历导入、用人负责人状态维护、面试评价、工作台待办和告警提醒的完整链路。
- **不包含**：历史数据迁移、Boss 直聘 API 接入和飞书 API 接入。

## D-016 开发基线补充

[面试流程与评价最小配置](面试流程与评价最小配置.md)定义逐职级轮次、各轮可选人员与实际参与人的区分、简短评价字段、当前轮按钮及结束后的流转。按[决策 D-016](../../产品探索/产品决策记录.md)，HR可维护／下载／软删除全公司非评价业务记录，不能修改、下载或删除面试官评价，不能改写审计和历史快照。当前实际指派面试官可结束或跳过非终面，普通面试官不能跳过终面及 CTO面；CTO不参与仅由当前职位负责人按 D-019 确认。解除指派后原关系访问失效，历史快照由当前 HR和当前职位用人负责人按范围查看。公共校验使用公共规范的 MVP 默认值。


## D-018 异常规则与自动流转对齐

以[决策 D-018](../../产品探索/产品决策记录.md)及[最小配置第6节](面试流程与评价最小配置.md)为准：某轮无人优先取前面最近有效实际指派，无则取后面最近实际指派；整个流程无人则警告职位负责人并阻止流转。同场次同轮换人保留已有评价，不重评，未交责任转给接任人；终面须明确完成责任人且有效评价责任齐全并通过，自动进入HR沟通节点及待决策，不提供HR手动推进动作。终面缺评价有站内消息，与待决策后每3工作日提醒分开。

候选人仅未进入流程时可软删除，准入为待筛选、无推荐／邀约／面试／评价流程历史；进入流程后即使终止也不可删除。职位存在进行中流程时不可删除，无进行中时可软删除并保留关联历史，管理员可恢复。判重及合并仅同职位内，未面试先判重，实际面试结束后起算一年；跨职位建立独立应聘记录，不合并。

### 初筛推荐的重复活动流程准入

依据[决策D-020](../../产品探索/产品决策记录.md)，同一候选人在同一职位已有待邀约、面试中或待决策记录时，禁止另一条初筛记录推荐进入待邀约。拒绝后保持初筛，不创建下游任务；待筛选／初筛记录不占用准入位置，跨职位独立。具体匹配、提示与并发条件见[PRD D.1](产品需求文档.md)，验收见TS-DUP-020。历史判重及一年期限不替代本条活动流程检查。

### 前轮迟交待定的业务边界

按[决策D-021](../../产品探索/产品决策记录.md)及PRD E.5，已进入后轮后，前轮迟交待定不回退、不暂停后轮，不新增待决策／录用门槛，当前职位用人负责人负责补充评价。当前实际轮及最终承接轮待定仍阻断该轮通过；迟交不通过仍终止尚未终止流程。详情保留待定事实，终止后不恢复流程。验收TS-LATE-021。
