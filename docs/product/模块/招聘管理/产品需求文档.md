## 1. Summary

本项目建设 HRM 人资管理系统的招聘管理模块 MVP，承接飞书职位发布完成后的职位建档、候选人筛选、邀约、面试、评价和录用决策。飞书继续负责招聘需求创建、审批、职位发布和关闭，HRM 成为候选人及面试协作的管理系统。

一期通过 HR 人工登记职位和导入 Boss 直聘简历，验证技术部前端招聘的完整业务闭环。系统重点解决候选人状态不透明、面试评价不及时和招聘事项长期未推进的问题。

### 2.1 业务角色与责任指派

本节以[产品决策 D-013](../../产品探索/产品决策记录.md)为准。

- **HR成员**：系统业务角色。拥有该角色的用户可以按权限执行招聘管理操作，并查看全公司招聘数据。
- **HR负责人**：职位级责任字段。每个职位设置一名主责 HR，负责该职位的候选人跟进、邀约、面试创建并接收该职位的长期未推进提醒。最终录用由拥有 HR成员角色的授权用户确认，默认可由 HR负责人执行。
- HR负责人必须是 HR成员；HR成员不等于某个职位的 HR负责人。
- **职位用人负责人（简称用人负责人）**：从具备面试官角色的用户中按职位指定的主负责人，每个职位一名，不单独配置同名账号角色。负责该职位初筛、面试官安排、招聘决策及按权限修改评价；数据范围限定到负责职位，不默认拥有所属部门全部招聘数据。
- **面试官角色**：招聘业务角色，是被指定为职位用人负责人或本轮面试官的资格基础。账号角色列表包括 HR成员、面试官及平台系统管理员，不包含独立“用人负责人”角色。
- **本轮面试官**：面试级参与指派，在每一轮面试中单独指定，可以一次指定多人或临时更换；只有被指派用户可以提交自己的该轮评价。职位用人负责人不自动参与各轮面试，提交评价仍须有该轮指派。
- **终面完成责任面试官**：最后一轮中被指定的一名本轮面试官，负责点击完成终面，并作为该场面试负责人维护完成后的面试结果。
- **招聘角色**：用于面试模板匹配的岗位分类，如前端、后端；不属于用户授权角色。
- 一个用户可以拥有多个角色。角色、责任指派与实际操作人分别记录；多角色判定遵循公共规范第 3.2 节，不跨角色拼接数据范围与动作权限。

## 3. Background

### 3.1 现状

- 招聘需求创建、审批和职位发布已经在飞书运行，老板不方便切换到新的审批平台。
- 候选人简历来自 Boss 直聘，HR成员需要把简历和候选人信息录入可持续维护的系统。
- 面试评价目前主要以文案记录，候选人阶段、面试安排和后续决策不够集中。
- HR、用人负责人和面试官需要看到不同范围的招聘信息，但目前缺少统一的待办入口。

### 3.2 为什么现在做

团队希望通过真实业务实践全栈能力，公司也缺少招聘管理系统。招聘流程已有稳定的飞书前置流程，适合把范围收敛到“职位发布后到录用决策”的完整闭环。

### 3.3 约束

- 一期不复制飞书审批，不建设自建审批流。
- 一期不接入飞书 API、飞书日历、飞书消息和 Boss 直聘 API。
- 一期没有历史数据迁移。
- 简历和面试评价仍属于敏感人事数据，必须落实权限、审计和软删除。
- 面试时间以 HRM 记录为准；HR 负责在飞书日历发生变化后更新 HRM。

## 4. Objective

### 4.1 产品目标

在不改变飞书招聘前置流程的前提下，让 HRM 成为技术部前端招聘的唯一协作入口，完整追踪候选人从导入到录用、淘汰或放弃的过程。

### 4.2 试点结果

以下结果作为 MVP 验收结果，正式效率指标后置：

1. 试点职位都能关联飞书审批申请链接，并包含完整的职位必填信息。
2. 试点新增候选人都能关联一个职位，记录来源、简历、导入人和导入时间。
3. 候选人只能按授权状态流转，关键操作均能追溯到操作人和时间。
4. 每场面试都能在 HRM 中记录时间、轮次、面试官和结构化评价。
5. HR、用人负责人和面试官能在工作台看到自己需要处理的事项。
6. 长期未推进候选人按规则提醒职位 HR负责人和用人负责人，且不会提醒未参加过面试的候选人。
7. 试点验收中的越权查看、下载、修改和录用操作全部被系统阻止。

### 4.3 后续观察指标

试点阶段建立基础指标基线，同时保留审计和业务操作日志；指标口径、采集方式和一期通过门槛见[指标与试点基线](../../指标与试点基线.md)。正式埋点体系、独立看板和跨模块经营指标不属于一期范围。

## 5. Market Segment(s)

本产品服务的是需要共同推进内部招聘的人，而不是外部候选人。

| 用户 | 核心任务 | 主要约束 |
| --- | --- | --- |
| HR成员 | 把已发布职位和 Boss 直聘候选人建档，推动流程并确认最终录用 | 需要全局视角，不能重复维护飞书云盘和表格 |
| 用人负责人 | 判断候选人是否进入面试，安排面试官并做招聘决策 | 需要看到负责职位的招聘数据和完整简历 |
| 面试官 | 在面试前了解候选人，在面试后快速提交评价 | 只能处理授权范围内的面试和评价 |
| 系统管理员 | 维护账号、组织、字典、权限和审计 | 不因平台管理员身份自动获得全部业务数据 |
| 老板 | 审批招聘需求和查看飞书流程 | 一期不需要登录 HRM |

## 6. Value Proposition(s)

### 6.1 对 HR

- 一个位置查看全局职位、候选人、待评价和逾期事项。
- 简历直接进入 HRM，不再以飞书云盘作为中转。
- 状态、邀约、面试和录用记录集中保存，减少重复追问。

### 6.2 对用人负责人

- 直接查看负责职位的候选人和完整简历。
- 从工作台处理初筛、待决策和逾期事项。
- 用结构化评价和面试模板降低决策遗漏。

### 6.3 对面试官

- 从工作台直接进入自己的面试和候选人详情。
- 使用少量固定字段加文字补充提交评价。
- 在允许范围内查看同部门、同职位的其他评价。

### 6.4 相比当前做法的改善

HRM 不替代飞书审批，而是补齐发布职位后的协作空白。它把招聘主状态、面试安排和评价从分散文案变成可追踪记录，并用提醒推动责任人处理阻塞事项。

#### 主要页面

1. 登录、首次改密和账号状态页。
2. 角色工作台：待办、逾期面试、待评价和长期未推进候选人。
3. 职位列表与职位详情：来源、状态、负责人和候选人进度。
4. 候选人列表与详情：简历、阶段、邀约、面试、评价和变更记录。
5. 面试模板和字典配置页。

轮次配置页、当前轮按钮与自动流转以最小配置方案为交互基线；空列表展示引导创建，无权限仅反馈拒绝，关闭职位阻止新增，重复候选人展示对比确认，取消／未到场保留原场次并提供 HR替代安排入口，缺交评价展示独立待办。视觉稿可后续补充，不自行改变业务授权。

### 7.2 Key Features

#### 7.2.0 公共规则引用

本模块遵循[字段与表单校验规范](../../公共规范/字段与表单校验规范.md)、[权限与数据治理规范](../../公共规范/权限与数据治理规范.md)。本 PRD 只记录招聘管理特有的字段、流程和例外，不重复维护跨模块规则。

#### A. 平台能力引用与招聘责任指派

账号创建、登录、首次改密、重置、禁用及多角色授权统一引用[公共权限规范](../../公共规范/权限与数据治理规范.md)第2、3节，由[平台基础能力](../../平台基础能力/README.md)承载，不在招聘模块维护另一套账号规则。

招聘模块只维护业务责任关系：用人负责人是具备面试官角色的用户在职位上的指派身份；职位 HR负责人必须具备 HR成员角色。HR成员或管理员可解除并重新指定职位 HR负责人；变更影响后续待办、提醒和操作责任，不改写历史操作人。具体授权和指派变更后的任务处理以本 PRD G.1、G.3及D-013、D-016为准。

#### B. 职位建档与状态

字段含义、来源、修改历史与职位更正规则见[职位字段定义](字段字典.md#fields-job)；F-03至F-08本期产品定义按D-026至040收口；已有字段规则如下；各独立字段定义分别引用D-026至040，尚待实现验收。

HR成员只能为飞书职位发布完成后的职位建档。必填字段如下：

| 字段 | 规则 |
| --- | --- |
| 职位名称 | 必填 |
| 部门 | 必填，记录职位所属部门；不因同部门自动授予招聘数据权限，授权按G.1、G.3判断 |
| 招聘人数 | 必填，正整数 |
| 用人负责人 | 必填，每个职位一名，从具备面试官角色的用户中选择 |
| HR 负责人 | 必填，每个职位一名主责 HR成员 |
| 职位类型 | 必填，使用字典 |
| 办公方式 | 必填，使用字典 |
| 飞书审批申请链接 | 必填，作为来源凭证和追溯入口 |
| 发布时间 | 必填，飞书实际发布时刻，不晚于当前业务时刻；D-028 |

用人负责人接任按D-026由HR成员在职位配置一次更换，接任人须启用账号和面试官资格、填写原因；不修改实际面试责任、评价作者、快照或任务起点。仅平台管理员不能执行；关闭职位仍可接任。来源关系按D-027每个飞书申请只对应一个职位，重复拒绝并复用／重开原记录；软删除来源按恢复授权处理，不重复建档。同一职位资料和来源纠错按D-029及字段文档第6节执行，公共字典编辑引用公共规范D-030。

人数、发布时间更正及办公方式按D-028执行，具体准入、原因留痕和人数不足核实见[职位字段定义](字段字典.md#fields-job)第5.2节；不触发自动关闭或候选人终止，负责人及状态操作独立。

HRM 职位状态包括“可招聘”和“已关闭”。飞书关闭职位后，HR成员手动将 HRM 职位调整为已关闭，禁止新增候选人，但不影响已有候选人的面试、评价、待决策和录用。飞书重新打开后，HR成员手动恢复 HRM 职位为可招聘。

职位 HR负责人可以被管理员解除并重新指定，不在招聘模块内设计“HR负责人账号被禁用”的特殊流程。负责人变更只影响后续待办、提醒和可操作责任，必须记录解除和指定的操作人、时间及原因。

#### C. 候选人和简历

字段与历史索引见[候选人与简历字段定义](字段字典.md#fields-candidate)；来源、联系方式、简历版本及职位固定按D-031至034定义；F-04本期产品定义收口，尚待实现验收，已有规则继续有效。

候选人由 HR成员从 Boss 直聘取得后直接人工导入 HRM，不经过飞书云盘。Boss 直聘侧授权是 HRM 接收数据前的外部前置事实，HRM 不重复建设或核验授权、告知、撤回和授权状态，HR 只负责把具体招聘数据落地到 HRM。必填字段为姓名、联系方式、简历、来源渠道和应聘职位。每份候选人应聘记录只关联一个职位，同一人可在不同职位分别建立独立应聘记录，跨职位不合并。

系统记录来源标识、导入人、导入时间和状态历史。来源默认Boss直聘；HR记录真实外部ID或链接，无法取得则填写原因，允许录入并标识缺失；后续可补充同一候选人来源并留审计。详细字段与准入按D-031及[候选人与简历字段定义](字段字典.md#fields-candidate)，不以内部编号冒充来源凭证。没有联系方式不能录入。导入时按标准化后的姓名和联系方式提示重复：D-032标准化姓名相同且任一同类联系方式相同为强重复，另一项不同或缺失不取消强匹配；仅姓名相同不判重；联系方式相同但姓名不同提示 HR 判断。仅同职位判重和合并；未面试时先按姓名及联系方式判重，不应用一年期限；实际面试结束后，以最近一次实际面试结束时间起算一年。

HR 确认合并后，系统建立主记录与旧记录的合并关系。旧简历、面试安排、面试评价和状态历史不得被覆盖或销毁；当前使用的简历版本由 HR 明确选择，合并操作人、时间、原因和前后记录标识写入审计。

**F-04补充依据**：手机号及邮箱各至多一项、至少一项按D-032；同职位判重及D-020活动复核使用任一同类匹配。简历每次上传一份，成功自动当前、失败不切换且历史保留按D-033，合并仍HR明确选择。应聘职位建档后固定，误建及另建按D-034，不迁移原流程。字段及页面入口见[候选人与简历字段定义](字段字典.md#fields-candidate)。

#### D. 候选人阶段和邀约

候选人阶段只允许正向推进，不允许回退。淘汰和候选人放弃不可恢复。最终实际业务轮未完成、有效评价责任清单未齐全或存在待定时，候选人保持“面试中”。任一轮有效评价不通过则自动淘汰，停止后续面试，不要求补齐终面评价。候选人放弃由当前招聘环节列出的责任人员主动点击产生，不设置自动时限；公司取消、候选人取消、未到场、拒绝和失联均可作为放弃原因。

| 当前阶段 | 下一阶段 | 可执行角色／责任身份 | 关键条件 |
| --- | --- | --- | --- |
| 待筛选 | 初筛、淘汰、候选人放弃 | HR成员 | HR成员完成资料检查并推荐，或主动点击终止按钮并选择原因 |
| 初筛 | 待邀约、淘汰、候选人放弃 | 用人负责人；HR成员可主动记录候选人放弃 | 用人负责人初筛通过且通过D-020重复流程检查后进入待邀约；不通过进入淘汰；待补充仍停留在初筛 |
| 待邀约 | 面试中、淘汰、候选人放弃 | HR成员 | 招聘平台答复为同意后创建面试；其他终止结果需主动操作 |
| 面试中 | 待决策、淘汰、候选人放弃 | 用人负责人、面试官、HR成员 | 终面面试官点击完成面试，且该轮换人后的有效评价责任清单齐全且通过时自动进入待决策；任一轮有效评价不通过自动淘汰，或当前环节责任人员主动点击终止按钮 |
| 待决策 | 录用、淘汰、候选人放弃 | HR成员、用人负责人、面试官；录用仅 HR成员 | HR与候选人在 Boss 直聘确认可入职后，HR成员二次确认录用 |
| 录用、淘汰、候选人放弃 | 无 | 无 | 终止状态 |

筛选与邀约字段、可更正范围及拒绝／失联后再联系见[筛选与邀约字段定义](字段字典.md#fields-screen-invite)（D-036）。邀约状态为待邀约、邀约中、同意、拒绝、失联。HRM 只记录 HR成员在招聘平台上的邀约结果；状态变更必须填写备注。只有“同意”才能创建面试。

面试记录需要区分“待面试、面试进行中、已完成、公司取消、候选人取消、未到场”等状态或结果。D-035明确候选人整体“面试中”表示进入面试流程；HR记录候选人同意后创建场次，其初始为待面试，当前实际指派面试官点击开始才变为面试进行中并记录实际开始，预约时刻不自动开始。具体授权与异常边界见[最小配置第9节](面试流程与评价最小配置.md)。终面面试官点击“完成面试”后才算实际完成，并记录操作人、实际完成时间和面试结果；完成后HR成员或该场面试负责人可以修改非评价面试结果，修改必须记录前后值、操作人、时间和原因。公司取消面试时保留候选人面试中阶段并记录公司取消原因；HR 可以基于原邀约直接创建同一轮次的替代面试，不重新发起邀约。候选人取消或未到场时，分别记录原因和备注，也可以创建同一轮次的替代面试。公司取消、候选人取消、未到场、拒绝和失联都可以作为“候选人放弃”的原因；当前招聘环节责任人员都可以主动点击按钮变更，不设置自动时限。替代面试视为一次新的实际面试，创建新记录并关联原面试，重新指派、完成和评价；旧场次评价不能满足新场次门槛，也不能覆盖原面试证据。

#### D.1 初筛推荐的重复流程准入（D-020）

用人负责人从初筛推荐进入待邀约前，服务端检查同职位其他有效应聘记录：按D-032标准化姓名相同且任一同类联系方式相同，且已有记录处于待邀约、面试中或待决策时，拒绝推荐。排除自身；待筛选／初筛不占用准入位置，终止记录不按进行中拦截；跨职位仍独立。活动流程检查不使用一年期限，历史判重仍按D-018执行。

被拒绝记录保持初筛，不生成邀约、面试或下游待办，不变更原流程。提示已有流程当前阶段，只有确有面试安排才写“已安排面试”，原记录入口按当前权限开放。同时推荐最多一条成功，创建面试及修改候选人身份资料时复核，遵循公共并发、授权和审计规范。详见[决策D-020](../../产品探索/产品决策记录.md)、TS-DUP-020。

#### E. 面试与评价

模板与场次字段、计划／实际时间及异常补录见[流程模板与面试场次字段定义](字段字典.md#fields-session)（D-037）；评价与最终决策字段见[评价与招聘决策字段定义](字段字典.md#fields-evaluation)（D-038）。逐轮可选人员、评价默认字段及交互按钮见[面试流程与评价最小配置](面试流程与评价最小配置.md)。本节按 D-016 允许当前实际指派人员结束或跳过非终面；终面不可跳过。本节结合[产品决策 D-015](../../产品探索/产品决策记录.md)的一面跳过例外，多轮评价以 D-014 为基础，当前通过／淘汰及CTO不参与规则以[产品决策 D-019](../../产品探索/产品决策记录.md)和 E.4 为准。

- 面试由 HR成员创建，用人负责人指定本轮面试官。
- 面试轮次按首次安排时选择的招聘角色和面试职级匹配完整流程，后续沿用快照；招聘角色和面试职级不是职位必填字段。
- 面试模板由职位用人负责人维护负责职位、HR维护全公司职位；轮次包含名称、顺序、角色/职级、默认时长、评价模板和是否必经。
- 首次安排面试时必须选择招聘角色和面试职级，后续仅选择流程快照中的轮次；系统保存匹配模板、评价模板和关键配置快照，后续模板修改不改变已创建面试的历史。
- 单个职位允许按业务规则调整轮次，但不能移除职级必经环节；P4及以上标准流程为四环节，符合 D-015 时可跳过一面，CTO正常参加时保留该轮；负责人可按 D-019 确认其不参与。面试官按轮次指定，可以一次指定多人，也可以临时更换。
- 最后一轮业务面试（不含 HR沟通）可以指定多名面试官，但必须指定一名终面完成责任面试官；只有该面试官可以点击“完成面试”，并作为该场终面负责人维护完成后的面试结果。
- 改期只更新 HRM 中的面试时间；面试官更换只更新面试官；一期不与飞书日历同步。
- 终面面试官在面试实际发生后点击“完成面试”；计划时间经过或打开页面不能自动完成面试。
- 各场次按有效评价责任清单独立提交本人评价；同场次同轮换人复用已交责任，不要求新旧双方重评；评价包含面试结论、七项文字评价维度（基础能力、项目经验、技术栈、工程化、沟通能力、契合度、AI实践能力）、是否推荐、风险项和文字补充；各轮默认采用同一七维度框架，具体字段及脱敏示例见最小配置第3节；按 D-017 替代原两维度建议，不计算总分，建议职级不自动改变流程。
- 同部门、同职位的面试官可以查看其他面试评价，但不能修改或冒用他人评价；评价本人不提供修改权限，职位用人负责人可在权限范围内修改所属职位的评价，提交后的修改必须审计。

#### E.2 多轮面试与评价归属

**业务价值**：保留不同轮次、不同人员的独立判断，支持职位负责人和 HR追溯招聘依据。**目标用户**：本轮面试官、职位用人负责人及有权限的 HR成员。**成功指标**：各轮评价可定位到具体场次、轮次及评价人，按 M-006 验证可追溯性。

- 候选人有多轮业务面试，每轮可以有一个或多个实际面试场次；取消后的替代面试是新场次，关联原场次。
- 每个需要评价的实际场次中，每名被指派面试官分别提交本人评价；同一人参与两轮产生两份评价，同轮两人分别产生两份评价。评价展示场次、轮次、评价人、评价模板快照、提交时间、状态和修改版本。
- 不用一个候选人级评价字段覆盖多轮评价；负责人修改某份评价不改变其他轮次或其他人员的评价与原提交人。
- 候选人详情按流程顺序展示各轮面试及独立评价，再展示 HR沟通结果；待评价按“场次＋轮次＋评价人”列出，已提交前轮评价不会因下一轮开始而丢失。
- HR沟通由有权限的 HR成员记录结果和必要备注，保留实际操作人及时间；不生成结构化面试评价，不直接修改其他人员评价或代替最终录用确认。
- **终面为最后一轮业务面试**：P3-2／P3-3 的负责人二面、P4／P5 的 CTO三面均为对应流程的终面；HR沟通不是终面。P2／P3-1 主面试官二面为终面，即使跳过一面也不改变该轮身份。
- **待决策门槛仍仅检查终面**：终面明确完成且该场终面换人后的有效评价责任清单齐全且通过（CTO不参与按 E.4 承接）；前轮缺交评价保留待办，不阻断进入待决策，也不新增安排下一轮前必须评价齐全的限制。不得把 HR沟通当作终面完成动作或新增阻断条件。
- 具体职级仅在首次面试安排时选择，匹配完整轮次流程并保存快照后按轮次安排；不得因每轮独立选模板丢失前轮、无记录删除流程环节或无记录绕过 CTO面，负责人不参与例外按 D-019 留痕；一面跳过按 E.3 保留例外记录。已创建场次及评价快照不随后续模板修改变化。

#### E.3 一面跳过与直接从二面开始

当一面人员无可用时间或多个候选人同时到达时，可由原二面对应人员直接承担实际面试。例外应用于目标候选人，不修改标准模板；按 D-016 由当前场次实际指派的面试官执行，仅非终面可跳过。

| 职级 | 标准路径 | 一面跳过后的实际路径 | 实际评价 |
| --- | --- | --- | --- |
| P2／P3-1 | 业务一面→主面试官二面→HR沟通 | 主面试官二面→HR沟通 | 主面试官提交本人二面评价，以亲自面试与反馈完成把关 |
| P3-2／P3-3 | 主面试官一面→负责人二面→HR沟通 | 负责人二面→HR沟通 | 实际二面人员提交本人二面评价 |
| P4／P5 | 高级开发一面→负责人二面→CTO三面→HR沟通 | 负责人二面→CTO三面→HR沟通 | 二面与 CTO面各参与人分别提交评价，CTO正常参加时仍执行该轮；不参与时按 D-019 承接前一有效实际轮评价 |

- 一面保留原节点及编号，明确标记“已跳过”，填写原因、实际操作人、操作时间及后续承接轮次；二面实际人员仍需单独指派，不自动继承原一面人员身份。
- 未发生的一面不生成评价或缺交待办；若一面原有安排，其历史安排保留并显示跳过原因，原一面待办停止。若已经完成一面，则不得事后跳过或删除其评价。
- 实际面试反馈归属于实际二面场次和人员，不代原一面人员提交，不将二面重新编号为一面；候选人详情区分“已跳过”与“已面试但评价未提交”。
- 不新增逐轮评价齐全才能安排后续轮次的门槛。低中职级二面完成且终面有效评价责任清单齐全并通过后自动待决策；高级职级正常参加 CTO时，二面结束不等于终面完成；负责人确认 CTO不参与时，按 D-019 将前一有效实际轮作为最终评价承接轮。
- HR沟通继续只记录结果。普通面试官不能跳过终面二面或 CTO面；负责人 CTO不参与例外按 D-019 执行；P4／P5 的非终面二面按 D-016 可跳过，不能省略终面完成与评价动作，也不改变邀约同意等安排前置条件。

#### E.4 通过流转、不通过终止与最终评价承接

以[决策 D-019](../../产品探索/产品决策记录.md)为当前业务基线。实际业务轮结束后，存在通过反馈且无不通过／待定反馈才自动激活下一轮待安排；非终面缺交不阻断，合法跳过非终面另按例外执行。已提交待定保持当前节点，由有评价修改权限的当前职位负责人记录补充依据、更新评价版本，确认通过后再判断流转。任一轮有效评价不通过（包括前轮迟交）直接将尚未终止的流程置为淘汰，停止后续业务面试和相关待办／提醒，不再等待终面补评；修改历史评价不恢复终止状态。多人结论冲突时不通过优先。

CTO无时间参与时，仅当前职位用人负责人可以对该候选人点击“CTO不参与”并填写原因；保留原节点、原指派和变更快照。前一有效实际业务轮成为最终评价承接轮：必须已实际完成、有明确有效责任人、换人后的有效评价责任清单齐全且通过。以原评价版本建立引用，不复制或伪造CTO评价。缺评价则提醒该轮当前缺交责任人；没有有效前轮则警告负责人并阻止流转。满足条件自动激活HR沟通并进入待决策；未执行CTO待办停止。CTO已实际完成后不能用此操作抹去历史。

同场次同轮换人复用已提交评价、未交责任交接；取消／未到场后的替代面试属于新实际场次，重新完成并评价。面试发现职级不匹配仅记录建议职级及依据，不直接修改原安排职级或后续流程。

#### E.5 前轮迟交待定（D-021）

以[决策D-021](../../产品探索/产品决策记录.md)为准：已经合法进入后轮后，前轮迟交／授权修改为待定不回退阶段、不取消场次、不阻断后续安排或结束，不追加待决策及录用门槛。详情标明该轮待补充，当前职位用人负责人按已有权限补充修改并保留版本；工作台展示负责人待处理项，不新增外部通知或提醒频率。HR不获得评价修改权。

当前实际轮或CTO承接最终评价轮的待定仍按D-019阻断该轮通过；前轮不通过继续淘汰尚未终止流程。已终止流程不因历史评价变化恢复或切换终止结果，终止后停止活动待办，保留历史证据。验收见TS-LATE-021。

以 D-016 为准，先前待明确项采用以下口径：

1. HR成员修改、下载及软删除范围为全公司招聘业务记录，排除评价、评价附件／版本、审计和不可变快照；平台账号管理仍由管理员承担。评价修改仅由当前职位用人负责人按职位授权执行。
2. 当前 HR和当前职位用人负责人可以查看对应范围内历史快照；原参与人解除指派后不能凭历史身份继续访问。负责人可跨部门被有效指派，但不扩大为部门权限；移除面试官角色使负责人资格授权失效，未完成任务显示待重新指派。
3. 面试模板按职位、岗位分类与职级组合维护；负责人维护负责职位，HR维护全公司。各轮在配置页提供候选人员名单，具体场次另行实际指派。
4. 最近实际人员兜底、同场次同轮换人及删除准入按 D-018 执行；当前实际指派面试官可结束非终面并跳过非终面；普通面试官禁止跳过终面及 CTO面；CTO不参与仅由当前职位负责人按 D-019 确认，终面结束由指定完成责任人执行。HR维护安排、改期、取消、未到场及非评价结果记录；所有状态操作仍受前置条件限制。
5. 各轮职责及状态按钮、终面反馈齐全后的自动流转，以[最小配置方案](面试流程与评价最小配置.md)为实现与验收依据。

#### G.4 权限验收要求

按钮级交接见[按钮权限矩阵](页面交互与按钮权限.md#buttons)，按公共权限规范第3.4节执行展示与提交校验。该矩阵引用G.1及业务状态规则，不新增权限。TS-BTN-023／024验证按钮反馈与服务端一致性，均待执行。

验收入口见[招聘管理测试场景](../../验收与追踪/招聘管理测试场景.md)中的 TS-AUTH-001、TS-AUTH-002、TS-INT-003、TS-INT-006 和 TS-GOV-003。至少覆盖管理员无业务角色、角色正确但记录越界、未被指派、状态不允许、查看但不能下载、多角色授权完整性，以及负责人或指派变更后的当前授权校验。通用审计字段和拒绝反馈遵循公共规范；本模块额外验证评价修改与面试结果修改互不替代、职位关闭不阻止已有候选人授权流程、恢复软删除不恢复终止候选人阶段。G.3 对应场景按 D-016 和最小配置方案的预期验收。

#### H. 字典

职位类型、办公方式、招聘角色、面试职级、候选人来源渠道、面试结论、推荐结果、风险项、淘汰原因和候选人放弃原因均为可维护字典。候选人放弃原因至少包括公司取消、候选人取消、未到场、已接受其他机会、不再求职、薪资原因、时间安排、失联、个人原因和其他。已被业务记录使用的选项只能停用，不能直接删除；历史编辑、换值及提交复核统一引用公共字段规范D-030。

### 7.3 Technology

本 PRD 不规定具体前后端技术栈。实现必须满足以下产品约束：

- 状态变更、权限判断和审计记录需要在服务端生效，不能只依赖前端按钮隐藏。
- 简历附件访问需要进行授权校验并记录下载审计。
- 工作日提醒统一按东八区计算。
- 后续接入飞书 API 时，职位来源字段与 HRM 招聘协作字段需要支持分权维护，不能覆盖已有候选人流程。

### 7.4 Assumptions

| 假设 | 当前处理 | 需要验证 |
| --- | --- | --- |
| HR 愿意把新增职位和候选人迁移到 HRM | 以 HRM 作为后续招聘协作入口 | 试点建档成本和切换阻力 |
| 用人负责人会维护初筛和决策状态 | 设置责任人、工作台和逾期提醒 | 状态责任是否清晰 |
| 面试官愿意填写结构化评价 | 保留文字补充，结构化字段保持少量 | 填写时长和完成率 |
| 公司允许 HRM 保存简历和评价 | 一期避开更敏感的薪酬、合同和档案数据 | 权限和合规评审 |
| 工作台能减少跨表格跟进 | 优先聚合待评价、逾期和长期未推进 | 试点使用行为 |

## 8. Release

### 8.1 第一阶段：基础能力

完成独立账号、首次改密、用户和部门、角色、字典、基础权限、审计框架和软删除能力。

### 8.2 第二阶段：招聘闭环

完成职位建档、职位关闭/恢复、候选人导入、重复提示、候选人阶段、邀约状态、面试模板、面试安排、评价和录用决策。

### 8.3 第三阶段：工作台与试点

完成角色工作台、待评价和逾期面试、长期未推进提醒、权限验收和技术部前端招聘试点。试点通过后再决定是否扩展到其他团队。

### 8.4 后续版本

- 飞书 API 同步职位和职位状态。
- Boss 直聘或其他招聘平台 API 接入。
- 受控批量导出和更完整的数据保留策略。
- 飞书消息或其他通知渠道。
- 绩效管理正式流程。
- 正式效率指标和数据看板。

### 8.5 发布门槛

- 关键业务流程可从职位建档走到录用、淘汰或候选人放弃；录用前置条件是 HR 与候选人在 Boss 直聘确认可入职。
- G.3 与 D-016 的已确认权限及默认配置同步到测试预期；角色权限和简历下载权限通过正向及越权用例。
- 候选人阶段不可回退，终止状态不可恢复。
- 重复候选人、关闭职位、面试完成、公司取消、候选人取消、未到场、替代面试和长期未推进提醒规则通过验收。
- 审计记录能够还原关键数据操作，且不能通过普通界面删除。

## 非阻塞待补充事项

以下事项不阻塞手工招聘 MVP，也不改变已确认的业务流程；在正式生产发布或建设对应能力前补充确认：

1. 首批试点的正式效率指标和目标值，指标基线见[指标与试点基线](../../指标与试点基线.md)。
2. 后续如公司制度要求数据保留期限，再补充主动删除、归档和法律保留规则；在此之前沿用一期暂不设置过期、软删除、管理员恢复和审计保留规则。
3. 公共校验已按 D-016 采用公共规范的 MVP 默认基线，不再作为开发前待确认项。


## D-018 异常规则与自动流转对齐

以[决策 D-018](../../产品探索/产品决策记录.md)及[最小配置第6节](面试流程与评价最小配置.md)为准：某轮无人优先取前面最近有效实际指派，无则取后面最近实际指派；整个流程无人则警告职位负责人并阻止流转。同场次同轮换人保留已有评价，不重评，未交责任转给接任人；终面须明确完成责任人且有效评价责任齐全并通过，自动进入HR沟通节点及待决策，不提供HR手动推进动作。终面缺评价有站内消息，与待决策后每3工作日提醒分开。

候选人仅未进入流程时可软删除，准入为待筛选、无推荐／邀约／面试／评价流程历史；进入流程后即使终止也不可删除。职位存在进行中流程时不可删除，无进行中时可软删除并保留关联历史，管理员可恢复。判重及合并仅同职位内，未面试先判重，实际面试结束后起算一年；跨职位建立独立应聘记录，不合并。
