# 平台基础能力

- **文档性质**：产品架构建议落地后的系统治理文档
- **建议来源**：产品结构评审建议，非原始业务需求
- **决策状态**：已确认纳入 HRM 产品结构
- **范围约束**：本文件明确能力归属和复用边界，不等于一期新增全部平台功能

平台基础能力属于 HRM 全系统能力，由多个业务模块共同复用，不归招聘管理模块独占。当前包含账号、组织、工作台、通知、字典配置和审计能力；字典已在现有MVP范围和US-601中定义，本次仅补齐归属。

## 能力边界

| 能力 | 系统级职责 | 招聘管理模块使用方式 | 当前阶段 |
| --- | --- | --- | --- |
| 账号 | 登录、首次改密、密码重置、禁用、离职和会话状态 | 复用用户身份和账号状态，不自行建设登录逻辑 | 当前 MVP |
| 组织 | 用户、部门、业务角色、组织关系和数据范围 | 使用角色、职位负责人及本轮面试指派判断招聘权限；部门身份不自动授予负责人数据范围 | 当前 MVP |
| 工作台 | 按角色聚合待办、逾期事项、提醒和统一入口 | 提供招聘待筛选、待评价、待决策和阻塞事项 | 当前 MVP |
| 通知 | 站内通知、已读状态、提醒生成和去重 | 生成面试待评价、逾期面试和长期未推进提醒 | 当前 MVP，暂不接入飞书消息 |
| 字典配置 | 提供选项维护、排序、停用和历史值展示机制，遵循公共字典校验规则 | 招聘维护所需字典分类、初始值及使用场景；不复制通用字典机制 | 当前 MVP，见US-601 |
| 审计 | 统一记录身份、角色、目标记录、操作、结果和变更摘要 | 提供招聘模块特有事件和敏感数据事件 | 当前 MVP |

## 复用规则

- 平台能力负责通用机制；业务模块负责业务触发条件、角色边界和验收场景。
- 平台管理员权限不自动获得招聘、绩效等业务数据权限。
- 招聘用人负责人按[产品决策 D-013](../产品探索/产品决策记录.md)从面试官中按职位指定，属于记录级责任身份；账号角色维护不配置独立同名角色。
- 模块不得绕过平台账号、组织、通知和审计机制自行保存一套平行状态。
- 模块需要新增系统级共性规则时，先更新本文件或公共规范，再更新模块文档。

## 当前不包含

- 飞书单点登录或组织架构自动同步。
- 飞书消息、邮件和短信等外部通知渠道。
- 跨模块统一数据看板和正式绩效工作台。
- 具体业务模块的状态流转、字段和审批规则。

## 权威关系

- 通用权限、审计和数据生命周期规则以[权限与数据治理规范](../公共规范/权限与数据治理规范.md)为准。
- 招聘模块的业务触发条件以[招聘管理 PRD](../模块/招聘管理/产品需求文档.md)为准。
- 具体需求到验收关系以[验收与追踪](../验收与追踪/README.md)为准。

## 产品落地与验收归属

见[产品能力与模块落地映射](../产品能力与模块落地映射.md)。公共规范定义规则，平台承载共用机制，招聘决定业务事实、触发条件和操作准入。工作台呈现与站内消息的已读状态不得代替招聘业务完成事实；具体交互缺口按映射中的待评审项处理。

## 人员基础规划缺口

现有账号与组织描述尚未独立定义人员身份与账号的关联，不能据现有用户管理断言已具备人员管理。用户明确同一人员通过角色及招聘职位区分职责；一人账号数量、人员范围、管理权限与生命周期待细化。推荐最小方案与阶段安排见[项目规划](../项目规划与阶段交付.md)，确认后回写公共规范、平台交互及招聘引用，当前不将建议作为已确认规则。
