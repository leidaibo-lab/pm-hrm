<a id="goals-scope"></a>

## 2 目标与范围

让管理员统一维护招聘参与人的身份、账号资格、部门和可选值，让内部用户通过有效账号处理当前授权任务，避免同人多角色生成重复身份、错误授权和无痕变更。

| 类别 | 本期范围 |
| --- | --- |
| 基础资料 | 实际使用HRM的内部人员、每人一个关联账号、可编辑预置角色、自定义角色及逐项权限／数据范围配置、平级部门、字典选项 |
| 平台支撑页面 | 登录及首次改密、工作台、本人站内消息、授权审计查询及软删除回收恢复 |
| 不包含 | 完整员工档案、岗位任职、身份证件、薪酬合同、无账号人员、外部面试官、单点登录／组织同步 |
| 业务边界 | 招聘职位负责人、场次实际指派、候选人阶段、评价及决策由招聘PRD定义；部门归属不产生操作权限；管理员初始配置不授予业务查看，本部门范围随当前归属重算 |

成功标准：人员创建及角色维护不产生重复身份；账号失效阻断访问；部门／字典停用保留旧关联、阻止新关联；授权拒绝无敏感泄露。人员和账号变更均保留操作证据；越权测试全部阻断且不泄露敏感信息；任务与消息按对应业务触发及去重规则验收。

## 3 角色与权限

下表说明预置角色初始职责，不以角色名称作为鉴权条件。管理员可编辑预置及自定义角色的权限、适用范围；实际入口与动作按系统权限目录及当前保存配置判断。普通业务角色配置管理权限后也必须满足对应管理范围，平台配置权不自动授予招聘数据查看。

| 角色 | 页面范围与允许动作 | 禁止或限制 |
| --- | --- | --- |
| 系统管理员 | 人员、账号、角色、部门及字典管理；授权平台审计及回收恢复 | 平台角色不授予候选人、简历或评价访问；不能自禁用或使最后有效管理账号失去完整管理能力 |
| HR成员 | 招聘授权任务与业务入口、本人消息、招聘审计；招聘权限另按招聘PRD | 初始无人员／组织管理及评价修改权限；调整后按当前配置与负责人指派校验，不得替他人提交评价 |
| 面试官／当前职位负责人 | 本人实际指派／负责职位对应任务与资料，本人消息、自身授权操作结果 | 同部门不自动授予业务权限；历史作者不保留当前访问权，不提供人员管理 |

按钮显示及提交复核统一按[公共按钮规范](../公共规范/权限与数据治理规范.md#34-按钮展示可用条件与提交校验d-023)执行，各页面只定义实际操作资格和业务条件。

## 4 业务概览

| 对象 | 表达的含义 |
| --- | --- |
| 人员 | 谁在使用系统，稳定身份 |
| 账号 | 如何登录 |
| 角色 | 具备哪些资格 |
| 部门 | 组织归属 |
| 招聘指派 | 具体业务责任 |

人员及账号一次创建，增加角色复用原身份。改名、改邮箱不替换历史作者；禁用不删除业务证据或自动完成责任。

### 4.2 角色交接与数据使用

1. 管理员维护身份与资格。
2. 招聘HR或负责人按当前有效资格指派业务。
3. 用户处理授权任务，业务模块更新事实与待办。
4. 平台展示消息及审计。

**资格失效**：账号禁用或移除资格立即改变当前访问。原业务责任由授权负责人在业务入口人工交接；平台只显示通用检查提示，不自动转交或泄露敏感任务。

### 5.1 人员与账号

人员新增时选择初始角色；已有人员调整角色，从人员列表进入详情页，在角色区点击“编辑角色”。角色分配复用当前人员与账号，不创建新身份；角色的权限及数据范围在[角色与权限配置](#shared-exceptions)维护。

#### 5.1.3 人员身份与账号关系

人员身份引用由系统生成且不可编辑；姓名、邮箱或部门变化均保持同一身份及历史作者。同名允许，不能按姓名自动合并人员。每人仅一个关联账号，登录邮箱使用人员新增／编辑页同一输入，不维护第二份独立邮箱。

本期不维护员工岗位及完整任职状态机；招聘职位、岗位分类和权限角色不能替代员工岗位。离职访问通过账号禁用处理，禁用不等同离职、启用不等同复职。账号可用性与下次登录需改密分别保存，需改密不作为人员任职状态。

#### 5.1.5 账号变化对业务历史的影响

### 5.7 角色与权限配置

目标用户为承担授权维护的管理员。管理员可按职责配置已有及新角色，避免必须通过固定名称角色才能取得所需权限。成功标准为：当前角色配置决定各页面授权，权限撤销后后续访问与提交立即受控，数据范围及实际业务责任不被绕过；功能验收逐项验证正向、范围越界、失权、依赖不足及管理账号保护。

**新增角色并分配给人员**

1. 从平台设置“角色管理”进入角色列表，点击“新增”；填写角色名称，勾选系统提供的权限，为每项权限选择适用数据范围。
2. 核对查看依赖及业务责任条件后点击“保存”，确认所选配置；成功后进入新角色详情，此时尚未绑定人员。
3. 从人员列表打开目标人员详情，在角色区点击“编辑角色”；保留或调整原角色，勾选新角色后保存并确认增删影响。
4. 人员详情刷新角色集合，后续访问按当前授权判断；账号禁用仍阻断访问，招聘动作仍须满足实际指派及状态条件。

**调整已分配角色的权限**

从角色列表或详情点击“编辑”，调整权限／范围并填写修改原因；保存时核对前后差异和关联人员数。确认成功后影响该角色的所有绑定人员，不必逐人重新分配；角色更名不替换人员绑定。只调整某个人的角色集合时，使用人员详情的“编辑角色”。

### 6.2 资格变更与管理连续性

启用账号不恢复旧会话或已交接指派；移除角色不改写原作者。管理员移除本人管理资格后不继续显示无权页面，邮箱更正或重置密码使本人会话失效时转登录页。人员与账号不存在删除／恢复、下载或批量导出入口；禁用不是员工离职办理，启用不是复职。

敏感操作失败不写入部分结果、不重发业务任务。部门、字典停用不撤销原业务权限，不强迫编辑其他字段时替换历史停用值。恢复回收记录不恢复终止招聘流程。

<a id="acceptance-delivery"></a>

## 9 验收与交付

| 能力 | 核心验收预期 |
| --- | --- |
| 角色与可选权限 | 预置及自定义可编辑，权限／范围依赖、绑定账号即时生效、并发、最后管理能力保护及页面返回完整验证 |
| 人员与多角色 | 一人一份身份及一个账号，增加角色不建新人，新增初始化、编辑回填及字段限制与保存结果一致 |
| 账号与管理员保护 | 禁用阻断访问，变更使会话失效；禁止自禁用和破坏最后有效管理能力；启用不恢复旧指派 |
| 部门 | 改名保持稳定关联，停用保留原关系和授权，只禁止新关联；无删除入口 |
| 字典 | 同分类名称不重复，排序确定，停用保留历史；不得用改名／新值替换既定业务语义 |
| 工作台与消息 | 当前授权、去重和责任起点正确，已读不完成任务；失权不泄露，业务终止停止适用提醒 |
| 审计与回收 | 摘要不越权，审计只读；恢复原因及二次确认，恢复不复活终止流程 |
| 页面交互 | 保存、取消、失败、拒绝、分页与返回上下文分别验证；无数据与加载失败区分 |

详细步骤和现有追踪统一使用[招聘管理验收附件](../验收与追踪/招聘管理验收附件.md#page-interaction-acceptance)中的人员、账号、部门、字典及平台场景。执行时记录版本、数据、结果及复测证据；越权测试全部阻断且无敏感泄露。执行结果记录在验收附件中。
