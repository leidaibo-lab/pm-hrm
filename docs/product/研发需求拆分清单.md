## 使用与完成约定

本清单是实施工作底稿，保存在产品协作区；正式需求仍从[交付入口](../output/README.md)阅读。每项的验收摘要用于明确拆分边界，字段、授权、状态、数值和详细步骤以链接的当前正式需求及验收为准。规则变更先维护权威源并导出，再同步任务，不能在任务系统另改业务政策。

RD编号用于承接工作，不替换既有US／TS编号。一个验收场景可能跨多个需求项；各项验证其对应行为，跨项场景在联合验收时完整执行。每项包含必要页面、业务处理、权限、异常、审计及测试，不以只完成前端或接口判定交付。

所有功能遵循当前“权限＋范围＋业务责任／状态”判定，文中HR、管理员及面试官表示业务使用者，角色名称本身不授予操作权。不得据旧用户故事摘要实现固定名称授权。本期不新增完整员工档案、Offer、外部同步接口、外部通知或统计看板。

每项统一完成条件：联合走查预期一致；实现及联调完成；本项验收与适用公共场景有执行证据；失败、越权及并发无部分保存；审计可追溯；缺陷处置和复测记录齐全。功能验收与试点效果分别记录。

## 需求明细

<a id="rd-01"></a>

### RD-01 部门维护与启停

- **目标角色与结果**：授权管理员维护招聘参与人的组织归属。
- **范围与入口**：部门列表、新增／编辑弹窗、启停及人员／职位选择引用。
- **验收重点**：新关联只用启用部门；停用保留原关系；重命名不换身份，无删除入口。
- **依赖与接入时点**：无业务前置；与02、04联合交付。
- **需求依据**：[对应PRD章节](../output/基础资料管理PRD.md#department-management)；故事 US-002。
- **验收入口**：[TS-ORG-024](../output/招聘管理验收附件.md#ts-org-024)。页面查询、返回、失败保留输入等同时执行验收附件“页面交互补充验收”中的对应页面场景。

<a id="rd-02"></a>

### RD-02 创建人员账号与维护资料

- **目标角色与结果**：授权管理员一次建立人员身份和登录账号。
- **范围与入口**：人员列表、详情、新增／编辑页；姓名、邮箱、部门及初始角色绑定。
- **验收重点**：同人多角色复用身份；失败无半条人员；改邮箱使旧会话失效，历史作者不变。
- **依赖与接入时点**：01；04授权和角色选择需共同联调。
- **需求依据**：[对应PRD章节](../output/基础资料管理PRD.md#person-management)；故事 US-001 US-002。
- **验收入口**：[TS-PERSON-022](../output/招聘管理验收附件.md#ts-person-022)、[TS-ROLE-022](../output/招聘管理验收附件.md#ts-role-022)、[TS-ACCOUNT-025](../output/招聘管理验收附件.md#ts-account-025)。页面查询、返回、失败保留输入等同时执行验收附件“页面交互补充验收”中的对应页面场景。

<a id="rd-03"></a>

### RD-03 登录改密与账号状态管理

- **目标角色与结果**：内部用户安全登录，管理员管理账号可用性。
- **范围与入口**：登录／首次改密页，详情中的重置密码、禁用及启用。
- **验收重点**：首次改密按规范；禁用拒绝访问；重置不自动启用，启用不恢复旧会话；自禁用和最后管理能力受保护。
- **依赖与接入时点**：02、04、06。
- **需求依据**：[对应PRD章节](../output/基础资料管理PRD.md#person-management)；故事 US-001 US-002。
- **验收入口**：[TS-ACCOUNT-025](../output/招聘管理验收附件.md#ts-account-025)、[TS-ADMIN-025](../output/招聘管理验收附件.md#ts-admin-025)、[TS-READY-003](../output/招聘管理验收附件.md#ts-ready-003)。页面查询、返回、失败保留输入等同时执行验收附件“页面交互补充验收”中的对应页面场景。

### RD-04 角色创建、复制与人员分配

- **目标角色与结果**：授权管理员按职责配置并分配权限。
- **范围与入口**：角色列表、详情、新增／编辑页及人员编辑角色弹窗；逐项权限／范围与查看依赖。
- **验收重点**：复制不复制绑定，新增不自动分配；依赖不足不保存；多角色不能拼接范围和动作。
- **依赖与接入时点**：与02共同完成身份授权闭环。
- **需求依据**：[对应PRD章节](../output/基础资料管理PRD.md#shared-exceptions)；故事 US-003 US-001 US-002。

### RD-06 管理能力保护与资格失效处理

- **目标角色与结果**：管理员保留有效管理入口，业务责任人能发现失效责任。
- **范围与入口**：共享角色编辑、人员解绑和禁用的管理能力保护；失权反馈与责任缺口。
- **验收重点**：并发不能让完整管理账号归零；不自动转交业务责任、不改作者；业务交接后保留任务起点。
- **依赖与接入时点**：02、04；与03联合验收，责任链随11、20复验。
- **需求依据**：[对应PRD章节](../output/基础资料管理PRD.md#shared-exceptions)；故事 US-003 US-002。

### RD-08 审计记录与授权查询

- **目标角色与结果**：授权管理员追溯关键操作且不越权读业务内容。

- **依赖与接入时点**：04；P1开始，随各业务项完成接入。
- **需求依据**：[对应PRD章节](../output/基础资料管理PRD.md#audit-recycle)；故事 US-602。

## 研发建任务与估算回填

建议将RD作为业务父项，研发按实际架构拆前端、服务端、数据／配置、联调及测试子任务；适用才建立，不为每项机械生成相同任务。数据库、接口和存储设计由技术评审决定。本清单不预设技术方案。

每项承接到任务系统时填写下列字段，所有空缺当前统一为“待研发／测试评估”：

| 字段 | 填写要求 |
| --- | --- |
| 业务父项及基线 | RD编号、链接、Git提交、PRD版本，保留US／TS追踪 |
| 实施子任务 | 具体实现交付物、父项关联及适用技术方案链接 |
| 负责人 | 研发、测试及设计协作人的实际姓名，不以角色代替已指派人员 |
| 估算与安排 | 工作量及估算假设、团队容量、依赖就绪日期、迭代、缓冲 |
| 准入与阻塞 | 关键规则理解一致、设计及外部输入就绪；未就绪项标明局部影响 |
| 执行状态 | 待联合交接与技术评估→可实施→实施中→待验收→已验收；阻塞单独记录原因 |
| 验收证据 | 环境、版本、步骤结果、缺陷、复测及验收人；只填真实执行记录 |

业务父项超过团队迭代容量时，按用户可观察结果继续细分，并保留所有子项与原验收的对应关系；禁止把权限、失败处理或审计删出完成范围来压缩估算。第一轮建议先联合评估RD-01至08及30、31的基础部分，再确定P1日期。
