# 对外输出产品需求文档格式模板

适用项目：pm-hrm。整理日期：2026-10-13。模板版本：1.0。

目标读者：编写需求的产品人员，以及接收需求的研发、测试、设计和业务评审参与者。用途：整理本期需求、需求评审、设计与开发交接、验收准备。交付形式：中文 Markdown。

本模板依据项目当前交付标准整理，提供填写结构，不是新的业务规则，也不表示已有产品完成联合交接或实现验收。正文中的 `【填写项】` 必须替换为当前业务定义；示例不代表新增本期范围。不适用项写明原因；真实未决项保留影响、责任与落实阶段，不以默认值代替确认。

## 使用说明与交付包

页面四类表头及列职责遵守[页面需求表头与用法规范](../产品经理工作与需求质量检查.md#page-table-standard)，以下示例直接采用统一列名。

| 文件 | 用途 | 使用本模板的位置 |
| --- | --- | --- |
| README.md | 阅读入口、顺序、配套与当前状态 | 配套格式一 |
| 产品项目总览.md | 系统目标、边界、架构、全局数据与依赖 | 配套格式二 |
| 基础资料管理PRD.md | 人员、账号、部门、字典及本期平台支撑页面 | 模块PRD正文模板 |
| 招聘管理PRD.md | 招聘业务需求 | 模块PRD正文模板 |
| 招聘管理验收附件.md | 本期详细场景、页面操作与工程追踪 | 配套格式三；当前同时承接基础资料与平台验收 |

新增模块按已确认范围增加对应PRD与验收，不按每个页面拆文件。总览使用系统视角，不套用模块页面结构；公共规范按对象或规则组织，保持唯一权威定义。

复制下方正文模板形成模块需求；第5章按实际业务组重复使用，组内分别定义列表、详情、新增／编辑及实际存在的弹窗／抽屉。相近新增／编辑共用字段与布局，用差异表说明模式；不存在的页面或操作不因模板而新增。

正式正文保留业务目标、当前规则、操作、异常、依赖与验收预期。内部讨论、决策编号、旧方案、AI工作记录不进入正文；页面操作表不放按钮、故事或测试编号，工程追踪进入验收附件。目录与链接辅助定位，不能代替当前页面定义。

## 配套格式一：交付入口 README

1. **交付说明**：【产品、本期范围、需求版本、目标读者及当前交接／实现状态】。
2. **阅读顺序表**：【顺序｜文档链接｜回答的问题｜必读角色】，本期依次为项目总览、基础资料PRD、招聘PRD、验收附件。
3. **共享配套**：【所有参与者必读及按能力必读条款；仓库或离线包访问方式】。
4. **原型与设计**：【链接、适用版本、覆盖边界及与PRD关系】。
5. **宣讲顺序**：目标与范围→角色及主链→页面与数据操作→异常→验收与依赖。

## 配套格式二：产品项目总览

| 章节 | 应填写的信息 |
| --- | --- |
| 1 文档信息 | 产品版本、日期、负责人、读者、当前交付状态及变化 |
| 2 产品目标与本期范围 | 问题、用户、价值、成功指标、流程起止、包含／排除及后续边界 |
| 3 角色与业务协作 | 全局角色、责任交接、平台管理与业务权限边界 |
| 4 业务架构与能力归属 | 能力地图、模块职责、基础资料与平台支撑、对应正式PRD章节 |
| 5 端到端流程与全局数据 | 主链、跨模块交接、关键对象与关联、数据来源与权威归属、全局数据流图 |
| 6 外部系统边界与共享机制 | 外部来源、人工／系统交接、共享机制责任及必读配套 |
| 7 非功能与运行约束 | 全局安全、审计、生命周期、性能与运行目标及真实未决项 |
| 8 验收、依赖与交付 | 本期覆盖、实施／发布依赖、验收入口、文档／交接／实现／效果的分别状态 |

总览不重复模块字段与页面操作，不将能力地图直接等同菜单或技术拆分。

## 配套格式三：验收附件

### A 文档与执行说明

【附件版本、适用产品及PRD版本、验收对象、执行角色、环境及数据准备。真实执行后填写执行日期、人员与证据；初稿不预填“通过”。】

### B 本期能力与需求覆盖

| 能力／实际页面 | 需求位置 | 关联故事／场景 | 覆盖情况及缺口 |
| --- | --- | --- | --- |
| 【基础资料、平台或业务能力】 | 【正式PRD准确章节】 | 【沿用已有工程追踪标识】 | 【已覆盖／部分／缺失／不适用及原因】 |

### C 页面操作与工程追踪

| 操作标识 | 页面／区域 | 按钮及触发入口 | 操作规则位置 | 用户故事 | 验收场景 |
| --- | --- | --- | --- | --- | --- |
| 【既有或按项目规范新增标识】 | 【实际页面与区域】 | 【实际文案及目标载体】 | 【准确规则锚点】 | 【关联标识】 | 【关联标识】 |

### D 详细验收场景（按功能重复）

| 项目 | 内容 |
| --- | --- |
| 场景编号／名称 | 【追踪标识／业务验证名称】 |
| 需求依据 | 【正式PRD页面、动作或规则的准确锚点】 |
| 角色与数据范围 | 【执行身份、当前责任及可操作记录】 |
| 前置条件 | 【账号、配置、对象状态、版本与测试数据】 |
| 执行步骤 | 【按实际入口、按钮和输入顺序逐步编号】 |
| 预期结果 | 【逐步说明页面反馈、状态、数据、责任、待办、历史及审计】 |
| 当前执行状态 | 【未执行／通过／失败／阻塞；只有实际执行后更新】 |
| 实际结果与证据 | 【实际观察、日志或截图、缺陷及回归记录】 |

同一功能覆盖正常、条件不足／拒绝及适用异常；新增和编辑分别验证差异。变更、失权、失败与返回场景按实际范围补齐，预期不能只写“操作成功”。

### E 结果与剩余事项

【记录执行范围、通过／失败／未执行项、具体缺口与影响、承担方及下一步；分别表达文档覆盖与真实验收结果。】

## 模板使用后的交付检查（内部填写，不复制进业务正文）

| 检查项 | 必须提供的证据 |
| --- | --- |
| 范围与输出覆盖 | 已确认范围、能力及实际页面能定位到正式PRD与验收；基础资料、平台、业务同等检查 |
| 九类信息覆盖 | 逐章已覆盖／部分／缺失／不适用与原因；占位项已处理，无虚构指标或负责人 |
| 页面独立阅读 | 列表与详情独立；新增／编辑共用字段且差异清楚；每页展示、按钮准入、结果、异常及返回完整 |
| 功能案例推演 | 每功能至少正常与拒绝案例，适用异常得到唯一预期；记录发现及处理 |
| 规则一致 | 角色、字段、状态、动作、图示、提醒与验收对应，无同一规则平行政策副本 |
| 阅读可用性 | 首次接触的读者无需聊天或讨论历史；正文无内部编号、残句、空引用、混页操作表 |
| 引用与图表 | 真实章节锚点与配套可达；图示有变更时检查语法及浅／深主题可读性 |
| 源与输出 | 修改权威源并生成输出，复核标题、节号、重复及语句；模板新增或导出成功不代表产品正文通过 |
| 结论与证据 | 记录文档／版本、检查范围、证据、未通过项及影响；联合交接、实现与效果分别记录 |
