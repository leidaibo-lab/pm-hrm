# Git 仓库到飞书的发布接入

本仓库提供正式交付内容和发布清单，平台负责拉取、转换及发布。Git 与飞书凭据、目标知识库、文档 ID 映射和发布记录由平台维护，不写入仓库。

## 平台读取入口

| 配置 | 本项目约定 |
| --- | --- |
| 仓库来源 | 下拉选择平台已配置仓库，复用仓库地址和访问凭据 |
| 首次读取分支 | 默认 `main` |
| 发布清单位置 | 默认 `docs/output/manifest.json`，相对于仓库根目录 |
| 内容根目录 | 清单的 `source.path`，当前为 `docs/output` |
| 最终发布分支 | 清单的 `source.branch`，当前为 `main` |

自动任务绑定仓库 ID，每次执行重新读取平台仓库配置。没有可用仓库时展示“去配置仓库”入口；仓库停用或缺少凭据时终止拉取并提示原因。

## 分支读取与一致性

1. 用首次读取分支（默认 `main`）解析提交 SHA，从该提交读取默认位置的清单。
2. 校验 `schemaVersion`、`source.branch`、`source.path` 及文档清单。分支一致时沿用上述 SHA，不重新读取浮动分支。
3. 若指定其他分支，解析该分支的提交 SHA，在同一清单位置重新读取清单。其 `source.branch` 必须与实际目标分支一致，否则报错，不递归跳转。
4. 所有文档及图片从最终确定的同一提交读取，发布记录保存 SHA。未提交或未推送的本地修改不属于发布内容。
5. 缺少分支、清单或文件、版本不支持、路径越界、重复 key、未知父节点或循环层级时，在写入飞书前报错，不静默使用其他分支替代。

## 文档契约

- `path` 相对于 `source.path`，不得越出内容根目录，也不得通过符号链接读取目录外文件。
- `key` 保持稳定，平台以项目、发布目标及 key 保存飞书文档和节点映射，改标题或路径仍更新原文档。
- `parentKey: root` 指向平台配置的发布目标节点；其他父节点须存在并参与发布。先创建父节点，再创建子节点。
- `order` 表示同级期望顺序，平台须核对飞书排序能力，不支持时提示。
- `publish: false` 或移出清单表示停止同步，保留原飞书文档，不自动删除。
- 转换标题、段落、列表、表格；Mermaid 渲染为图片上传。建立映射后替换包内 Markdown 链接，章节定位按飞书实际能力处理。
- 清单覆盖 8 份 Markdown，保留交付入口以承接 README 引用。HTML 原型不作为云文档发布，平台提供可访问入口或明确提示未发布，不生成失效链接。
- 重复发布相同提交不新增重复节点。平台说明更新对评论的影响，返回逐文档结果、链接、失败阶段和原因，部分失败不得报告整包成功。

## 项目侧发布准备

需求修改完成后执行 `python3 scripts/export_product_delivery.py` 和 `python3 scripts/check_product_delivery.py`，通过后提交并推送本次确认的源文档、生成输出及清单变更。清单是独立发布配置，业务正文仍由现有导出脚本生成。

首次接入验证默认分支读取、目标分支校验、SHA 固定、8 份文档层级、重复发布及缺失清单的错误反馈。本仓库配置不代表平台上述行为已经实现；Git 拉取、飞书鉴权、图示、链接和评论效果须平台联调验证。
