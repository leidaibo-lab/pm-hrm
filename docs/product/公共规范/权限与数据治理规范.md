## 一、数据敏感性

本期内部人员资料、候选人信息、简历及面试评价按人事敏感数据管理。敏感信息的查看、修改、下载、审计与保留分别执行以下规则；后续员工档案、合同、薪酬及绩效不纳入本期能力范围。

## 二、账号与组织基线

本文的“管理员”指具备对应管理动作权限的用户，不以绑定名为系统管理员的角色作为充分条件。各管理操作还须在其配置范围内；预置角色初始配置、权限目录及页面操作见基础资料PRD。

- HRM 使用独立账号体系和账号密码登录，不默认复用外部平台组织架构。
- 管理员创建人员及关联账号，禁用或重新启用账号，并维护部门、预置角色及自定义角色；本期不提供人员删除／恢复。
- 管理员创建用户时设置临时初始密码；用户首次登录必须修改密码后才能继续使用系统。
- 管理员重置密码后，用户下次登录必须再次修改；创建和重置操作必须写入审计记录。
- 按内部人员身份规则，本期人员使用稳定身份引用，每人一份信息、一个关联账号；仅管理实际使用HRM的内部人员，由管理员统一维护，人员与账号一次创建。姓名用于显示，邮箱作为登录标识并执行唯一校验，不能作为会因修改而替换历史作者的人员身份。增加角色不得新建同一人的人员或账号；不建设无账号人员库及完整员工档案。
- 部门变更更新组织归属，不自动授予招聘业务权限；账号禁用后禁止访问，历史记录保留原操作人和必要的历史关系。
- 一个用户可以绑定多个业务角色，实际业务权限按第3.2节的完整授权结果合并，不跨角色拼接动作和范围。
- 平台管理员权限不自动转化为全部业务数据权限；管理权限和数据权限必须分开控制。

<a id="21-部门归属与生命周期d-024"></a>

### 2.1 部门归属与生命周期

- 本期使用平级部门列表，每个人员关联一个部门。部门关联稳定，名称必填、按公共文本规则校验且在所有保留部门中不重复；创建默认启用，重命名不改变关联及历史证据。
- 管理员维护部门创建、重命名、停用和启用，本期不提供删除入口，不建设部门层级或多部门任职。
- 新人员及新职位只能选择启用部门；停用可作用于已有人员／职位关联的部门，原关联及业务权限保留，不自动迁移、禁用账号、关闭职位或终止业务。
- 编辑记录其他字段可保留原停用部门；若重新选择归属，仅允许启用部门。停用操作按按钮规范二次确认并提示影响。

<a id="22-人员资料与账号状态d-025"></a>

### 2.2 人员资料与账号状态

- 管理员查看、创建和修改本期内部使用者基础资料及其账号；未配置人员查看／编辑权限的用户没有相应人员详情／编辑权，仅按业务授权使用必要的人员显示和指派信息。本人资料自助编辑、人员删除／恢复、资料下载／导出本期不提供；账号启用不是人员恢复。
- 账号创建默认启用且需首次改密；可用性为启用／禁用，需改密是独立条件。禁用立即阻断访问，当前会话不能继续使用；启用要求重新登录，不恢复旧会话，保留角色和需改密标记，不自动恢复旧业务指派或终止流程。
- 管理员可更正邮箱，按公共格式和唯一性校验，确认前后值并填写原因；人员身份及历史引用不变，更正使会话失效，不自动重置密码或解除禁用。
- 管理员可对启用或禁用账号重置密码；重置使会话失效并要求下次登录改密，不顺带启用账号。密码内容不进普通日志。
- 禁用需原因；离职以禁用原因记录并阻断访问，不建设完整离职流程。禁止管理员禁用自己；账号禁用或角色调整须满足第3.5节的最后有效管理能力保护，按当前能力和并发结果判断，不按角色名称或旧页面人数判断。
- 角色至少一个，禁用账号可维护角色但保持禁用。资格变更按当前授权立即判断，历史作者不变；账号重新启用不覆盖已发生责任交接。
- 平台对禁用／角色移除仅给检查未完成责任的通用提示，不展示越权业务详情，不强制先交接后禁用，不新增外部通知、频率或自动责任转移。业务模块在其授权入口维护责任。

## 三、权限模型基线

- 权限至少拆分为查看、创建、修改、删除、恢复、下载、导出和管理配置等操作级别。
- 数据范围可按权限配置为全部数据、本部门、本人负责职位、本人实际指派记录；各权限只展示适用的范围，不能用业务范围配置替代实际责任及状态条件。
- 前端隐藏按钮不能作为权限控制；每个敏感操作都必须在服务端再次校验用户身份、业务角色、数据范围和记录状态。
- 多角色用户执行操作时，系统记录实际用户、作用角色、目标记录、操作时间和操作结果。
- 用户失去权限后，新数据和历史资料均按当前授权拒绝访问；保留历史作者及证据不保留访问权。

### 3.1 角色、权限与责任指派的定义

| 概念 | 产品定义 | 身份与授权边界 |
| --- | --- | --- |
| 人员 | 系统内部使用者的稳定自然人身份 | 每人一份人员信息，角色和指派变化不新增人员；历史作者关联该身份 |
| 账号 | 与人员关联的登录身份与认证状态 | 本期每人一个账号，与人员一次创建；认证状态不等于员工任职状态 |
| 用户 | 通过关联账号登录并执行操作的人员 | 操作始终归属于实际人员及账号，不能以角色或责任人替代操作人 |
| 角色 | 围绕一组业务职责定义的权限集合 | 权限集合由当前配置决定；平台管理权限不自动获得业务数据权 |
| 操作权限 | 对某类业务对象执行某个动作的授权 | 按“对象＋动作”描述，如候选人查看、简历下载、面试评价修改 |
| 数据范围 | 某项操作允许作用的记录集合 | 查看与操作分别判定，可查看不等于可修改 |
| 责任指派 | 用户与具体职位、项目、任务或记录的责任关系 | 按主责、参与和资格判断记录关系；指派本身不能绕过动作权限及状态条件 |
| 业务条件 | 操作成立所需的状态和前置事实 | 状态及前置事实须成立，仅有角色名称不能执行动作 |

### 3.2 授权判定与多角色合并

- 每次操作必须满足账号可用，并在至少一个授权角色下完整满足该操作的数据范围、适用的责任指派和业务条件。
- 多角色权限合并的是各角色完整授权结果，不能把角色甲的数据范围与角色乙的操作权限拼接成新的授权。例如仅在本人任务内可修改的角色，不因另一个角色可全局查看而获得全局修改权。
- 未明确授权的操作默认拒绝；当前角色权限、数据范围、责任及业务条件须完整成立。
- 模块可以将负责人定义为记录级责任身份；此时账号角色、负责人指派和具体任务参与分别判断，不必再维护同名账号角色，也不能因主责身份自动取得所有子任务参与权。
- 责任指派条件只适用于明确依赖该关系的操作；拥有全局查看权限的角色不要求被逐条指派，模块应逐项说明。
- 保留历史操作人、历史角色或责任关系用于追溯，不代表保留当前访问权限；每次访问仍按当前有效授权判断。

### 3.3 授权验收要求

每项操作验证合法授权、缺少动作权限、记录越界、指派失效及状态不允许的适用路径。角色、部门及指派变化后重新判断当前授权；页面、列表、搜索、工作台和附件采用同一范围，拒绝反馈不泄露敏感信息。

<a id="34-按钮展示可用条件与提交校验d-023"></a>

### 3.4 按钮展示、可用条件与提交校验

| 条件／场景 | 页面反馈 | 服务端准入与执行结果 |
| --- | --- | --- |
| 缺少完整操作授权 | 隐藏对应按钮；查看权不生成修改、下载、删除或配置按钮 | 直接请求仍拒绝；多角色按第3.2节完整合并 |
| 已有操作授权，业务条件未满足 | 禁用并说明安全、可修正的原因 | 不执行动作；非当前节点及已结束任务按页面定义展示必要动作 |
| 页面打开后权限或状态变化 | 更新反馈，不沿用旧页面判定 | 每次提交复核账号、角色、范围、指派、状态及业务前提；拒绝不泄露目标内容 |
| 必填或字段错误 | 按字段规范提示并保留合法输入 | 不部分保存；提交期间防重复执行 |
| 执行成功 | 刷新业务事实和按钮条件 | 并发、重试和审计按公共规则执行 |
| 终止、删除、禁用账号或录用 | 明确目标、后果并二次确认 | 原因按对应动作定义，不增加通用必填原因 |

系统权限目录只包含本期定义的动作，角色只能选择系统提供的权限项；禁止功能和自动流转不产生新按钮，不通过配置绕过业务条件。

<a id="role-permission-configuration"></a>

### 3.5 角色与权限配置

#### 配置权限与数据范围

- 本期采用预置角色、自定义角色及可选权限。预置角色提供初始配置，预置和自定义角色均可编辑权限及适用的数据范围；角色名称、类型和历史作者身份本身不授予权限。预置角色调整后不因登录、重启或新增人员而恢复默认值。
- 角色新增／编辑为全局授权管理能力，获得该权限的用户可维护系统目录内的业务权限与范围；人员角色分配的范围限制作用于被分配人员，不自动限制该角色自身的业务范围。管理员分配角色前须看到该角色当前权限及范围，分配动作二次确认并审计；只有配置权而未绑定相应业务权限时，管理员不能访问业务原文。
- 管理员按系统提供的“对象＋动作”权限目录配置角色；查看、编辑、下载、删除、恢复及配置分别选择。目录不包含尚未开放的员工档案、薪资、评价下载、任意导出或流程强制推进权限。权限选择只授予已有功能，不创建新功能。
- 每项权限分别配置适用数据范围，至少选择一个；同项权限可选择多个适用范围，其记录集合取并集。全部数据已经覆盖其他范围，不重复选择。未选择权限时对应范围不生效，不以隐藏范围的旧值产生授权。
- 需要页面查看才能完成的动作，必须在同一角色内同时配置所需查看权限，且查看范围覆盖操作范围；保存时明确列出缺少的依赖，不静默勾选或扩大查看范围。对恢复、人员责任配置等只需安全摘要的操作，不因此要求业务正文查看权。

#### 配置变更与生效

- 角色权限及范围变更保存成功后，对所有绑定账号的下一次查询、附件访问和提交立即按新配置判断；已打开页面不能沿用旧权限。取消、失败或并发版本冲突不部分更新权限，不撤销已完成事实；失权用户退出无权页面并刷新工作台。
- 审计记录角色稳定引用、当时名称、类型、权限与范围的前后值、变更原因、实际操作者、时间和结果；历史操作按当时授权证据追溯，当前访问按最新配置判断。撤销权限不改历史作者、不自动交接责任、不重置提醒起点。

#### 最后有效管理能力保护

- 最后一个启用管理账号保护按实际能力判断，不能只计名为“系统管理员”的角色。任何角色编辑、人员角色调整或账号禁用后，必须仍有至少一个启用账号具备全部数据范围的人员查看、账号启停、人员角色分配、角色查看、新增与编辑权限；并发提交仍须保护该条件。

<a id="configurable-data-scope"></a>

### 3.6 可配置数据范围

| 范围 | 判定依据 | 适用边界 |
| --- | --- | --- |
| 全部数据 | 当前系统内该权限对应对象的记录 | 不绕过对象状态、责任指派、本人提交及禁止事项；不是全功能管理员权限 |
| 本部门 | 登录人员当前部门与目标记录归属部门相同 | 人员／账号取目标人员部门；职位取职位部门，候选人、简历、场次及评价随所属职位部门；不是按创建人部门判断 |
| 本人负责职位 | 登录人员是目标职位当前有效HR负责人或用人负责人 | 子记录沿所属职位判断；用人负责人专属动作仍要求用人负责人身份，HR负责人身份不能替代 |
| 本人实际指派记录 | 登录人员是当前有效实际场次参与人或完成责任人 | 只涵盖所参与场次、对应候选人必要资料及该权限允许的关联证据，不因此看见同职位全部候选人；提交评价仍仅本人责任 |

- 部门、负责人及指派变化后，按当前归属和有效关系重新判断；历史名称或作者不保留访问权。账号禁用始终阻断访问。
- 人员／账号权限适用全部数据或本部门；部门、角色、字典与全局平台配置没有职位／场次归属，只适用全部数据。本人消息及改密是登录用户自身能力，不通过角色配置扩大到他人。
- 招聘对象权限可配置上述四种范围；新增职位只适用全部数据或本部门，以提交的职位部门校验。向已有职位新增候选人／场次按目标职位及假定新增后记录的关系校验，不能以创建人身份自动获得访问。
- 查看及提交均须校验范围；更新改变记录归属时，原记录和保存后的目标归属都必须在操作范围内，不能通过编辑部门把越界记录带入或移出授权范围。
- 审计与回收按目标业务对象归属判断范围，保留追溯引用；无法确定归属的旧记录不得猜测或按操作者部门放行，仅全部数据授权可访问安全摘要。恢复不自动授予业务正文查看权。

## 四、敏感数据访问

- 查看、修改、下载和导出敏感数据分别授权，不因拥有查看权限自动获得下载或导出权限。
- 附件访问必须经过权限校验，不能仅凭不可过期的公开链接访问。
- 敏感数据在列表、日志、错误信息和通知中按最小必要原则展示。
- 密码、令牌、完整附件路径和其他认证信息不能写入普通日志。
- 模块如需批量导出，必须明确角色、数据范围、字段范围、审批要求、文件有效期和导出审计。

### 4.1 产品文档与参考资料脱敏

- 产品需求、示例、流程矩阵及参考截图使用匿名编号或业务身份替代真实姓名，文档与图片须同时脱敏，不在仓库保存明文姓名映射。
- 图片采用覆盖并重新编码的方式去除原姓名像素，不用可撤销图层或模糊作为脱敏结果；不附带未脱敏原图。
- 脱敏不等于加密。确需可还原的人员名单时，原始名单及映射应在另行授权的受控存储中加密保存，密钥与数据分开管理；不把密钥、原始名单或映射写入产品文档及仓库。
- 文档匿名编号仅用于示例关联，不作为系统账号、职位负责人或面试官授权依据。

## 五、软删除与数据生命周期

- 业务数据默认采用软删除，不直接物理删除主记录、附件引用和过程记录。
- 软删除记录默认不出现在正常列表、搜索和统计中；恢复入口只提供给管理员或模块明确授权的角色。
- 删除必须记录操作人、操作时间、删除原因和原记录标识。
- 恢复必须记录恢复人、恢复时间、恢复原因和恢复前后状态。
- 审计记录采用追加方式保存，不提供普通业务删除入口，也不能无痕修改。
- 所有候选人的简历永久保留，不因录用、淘汰、拒绝邀约、候选人放弃或资料超过一年而自动清理；当前及历史简历版本沿用既有保留规则。保留用途为招聘历史参考及后续人才库使用。
- 保留不改变查看、下载及责任指派授权。HR可在当前授权范围内查看历史资料，作为再次邀约的参考；历史拒绝不代表当前同意，再次邀约和进入招聘流程仍须满足对应业务条件。
- 本期不自动过期清理其他敏感数据；业务软删除保留主记录、附件引用、过程和审计证据。简历永久保留不扩大为所有人事敏感数据的永久保留政策。

## 六、审计基线

至少审计以下行为：

- 登录、登出、密码创建、重置和修改。
- 用户、部门、角色和权限配置变更。
- 敏感数据查看、修改、下载和导出。
- 业务记录创建、修改、状态变更、软删除、恢复和合并。
- 权限拒绝、校验失败和高风险操作失败。

| 审计信息 | 记录内容 | 约束 |
| --- | --- | --- |
| 操作者 | 实际人员及关联账号 | 不以角色或责任人替代操作人 |
| 作用角色 | 实际执行所依据的授权角色 | 多角色按完整授权结果记录 |
| 操作时间 | 实际发生时刻 | 使用公共业务时区 |
| 目标记录 | 对象及稳定记录引用 | 支持回溯原记录 |
| 操作类型与结果 | 实际动作及成功／失败结果 | 包括适用的拒绝、校验及高风险失败 |
| 变更摘要 | 必要前后值、原因和结果 | 不记录密码、令牌等认证秘密；敏感内容按最小必要展示 |
| 责任证据 | 适用职位／任务及当时责任身份 | 依赖责任指派授权时记录，不作为当前访问权 |

## 七、运行容量与备份恢复

### 验收规模

| 对象 | 规模基线 | 适用说明 |
| --- | --- | --- |
| 使用人员 | 预计不超过30人，按30人同时操作验收 | 容量基线，不是账号创建上限 |
| 候选人简历信息 | 至少10,000份 | 包含附件及查询、评价所需关联记录；达到该数量不拒绝新增 |

### 响应与上传目标

以下目标在上述数据量及并发条件下验收。

| 操作 | 时间上限 | 计时范围 | 成功判据 |
| --- | --- | --- | --- |
| 列表查询／翻页 | 3秒 | 点击查询或翻页至结果可见 | 结果及权限正确 |
| 保存评价 | 3秒 | 点击保存至保存完成反馈 | 持久化成功、刷新可读取；不提前显示成功缩短计时 |
| 简历上传 | 60秒 | 开始上传至校验、附件保存及成功反馈完成 | 文件符合附件准入；失败不形成可用版本、不切换当前简历，重试不重复创建 |

### 备份与故障恢复目标

| 项目 | 目标 | 判定口径 | 恢复要求 |
| --- | --- | --- | --- |
| 备份 | 每周一次 | 相邻成功备份间隔不超过7天；任务启动不视为成功 | 业务数据、简历等附件、关联引用及审计可一致恢复 |
| 恢复点（RPO） | 最多丢失7天数据 | 可恢复数据点距故障发生不超过7天 | 不以失败备份的计划执行时间计算恢复点 |
| 恢复时间（RTO） | 不超过48小时 | 故障导致不可用至恢复核心使用 | 登录、授权访问及核心招聘操作可用；仅启动服务不算完成 |

### 验收证据

- 性能验收记录客户端、服务端、网络及存储条件，采用合法脱敏数据、真实附件，记录每次操作耗时及结果；上传包含20 MB边界文件。
- 用户侧断网及上传中断单独验证失败与重试，不与正常网络条件下耗时混算。
- 实际演练备份恢复，核对主记录、附件、版本引用、权限和审计一致性；记录备份时间、恢复点、故障开始及恢复完成时刻。

## 八、模块落地要求

每个模块的 PRD 需要补充：

1. 模块角色及角色之间的职责边界。
2. 数据范围和操作权限矩阵。
3. 模块敏感数据类型及其查看、下载、导出规则。
4. 删除、恢复、归档和保留规则。
5. 模块特有的审计事件。

招聘管理模块的候选人告警、候选人去重、职位关闭和简历处理规则属于模块需求，详见[招聘管理PRD](../模块/招聘管理/产品需求文档.md#features)。
