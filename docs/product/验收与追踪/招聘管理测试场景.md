# 招聘管理测试场景

以下场景用于连接用户故事和 MVP 发布验收。按 D-014，本文件“最后一轮／终面”指最后一轮业务面试，不含 HR沟通。正常通过路径的场景默认已提交反馈均为通过；评价齐全按同场次换人后的有效责任清单判定。CTO正常参加与负责人确认不参与分支分别验收；不通过／待定分支按 TS-ALIGN-020。每个场景包含前置条件、角色、动作和可观察结果，具体测试数据由技术设计阶段补充。

## TS-AUTH-001：多角色用户和数据范围

**测试目标**：验证系统管理员、HR成员、面试官角色及职位用人负责人责任身份的授权边界。

**前置条件**：准备系统管理员、HR成员、普通面试官及 HR成员＋面试官多角色账号；在同部门设置职位 A、B，各有候选人、简历和面试。用户甲具备面试官角色，仅负责职位 A，未被指派职位 B 的面试；多角色用户乙也仅负责职位 A。

**角色／责任身份**：系统管理员、HR成员、面试官、职位用人负责人。

**步骤**：

1. 使用仅有系统管理员角色的账号访问候选人详情和下载简历。
2. 使用 HR成员访问全公司职位、候选人和简历，下载职位A、B的简历；尝试下载评价、评价附件及执行批量导出。
3. 用户甲访问职位 A 的候选人资料，再访问同部门职位 B 的候选人资料、执行 B 的初筛和修改评价。
4. 被指派面试官查看候选人资料并尝试下载简历。
5. 用户乙查看职位 B 的候选人，再尝试为未被指派的面试提交评价、修改非本人负责职位的评价。

**预期结果**：

- 系统管理员不能仅凭平台权限访问招聘敏感数据。
- HR成员按HR角色查看全公司招聘数据并下载非评价业务资料，无需逐职位下载指派；评价及评价附件下载、批量导出仍被拒绝。
- 用户甲可凭职位负责人关系查看 A 的资料；对 B 的访问、初筛和评价修改均被拒绝，同部门身份不授予权限。
- 被指派面试官可查看授权资料，但不能凭面试官角色下载简历。
- 用户乙可凭 HR角色查看 B，但不能将 HR全局查看范围拼接成未被指派面试的评价提交权或非负责职位的评价修改权。
- 每次允许或拒绝访问都有审计记录，记录实际用户、作用角色及本次授权所依据的责任指派。
- PRD G.3 已按 D-016 收口，HR全公司非评价业务权限、历史访问及当前轮操作按最新矩阵验收。

## TS-AUTH-002：职位用人负责人指派与轮次参与隔离

**测试目标**：验证负责人来自面试官角色用户，且职位负责人身份不自动产生本轮面试参与权。

**前置条件**：准备有面试官角色的用户甲、乙，以及只有 HR成员角色的用户丙；建立职位 A，指定甲为用人负责人，某轮只指派乙参与面试。

**角色／责任身份**：有权维护职位负责人指派的用户、面试官、职位用人负责人。

**步骤**：

1. 查看账号可配置角色，尝试将无面试官角色的丙指定为职位用人负责人。
2. 将甲指定为 A 的用人负责人，保存并查看负责人和审计记录。
3. 甲查看 A 的候选人，处理处于初筛阶段的候选人，并修改 A 下乙已提交的评价。
4. 在甲未被指派本轮时，尝试以甲身份提交本人本轮评价。
5. 将甲指派到下一场面试的具体轮次，再以甲身份提交本人评价。
6. 在甲未被指定为终面完成责任面试官的终面中，尝试完成终面和修改完成后的面试结果。

**预期结果**：

- 账号角色列表不包含独立“用人负责人”；丙不能被指定为职位用人负责人，每个职位有一名负责人。
- 甲的职位权限以面试官角色及 A 的负责人指派为依据，指派记录可追溯。
- 甲可查看负责职位资料、执行初筛并按规则修改所属职位评价；评价修改保留版本、修改原因和审计。
- 甲未被指派本轮时不能提交本人评价；被单独指派后才可提交本人该轮评价，不能代乙提交。
- 负责人身份不授予终面完成或完成后的结果修改权限，步骤 6 被拒绝。

## TS-JOB-001：职位建档、关闭和恢复

**测试目标**：验证职位来源和关闭状态规则。

**前置条件**：准备一个飞书职位发布完成的来源链接和一个未发布职位来源。

**角色／责任身份**：HR成员。

**步骤**：

1. 使用未发布职位来源尝试创建 HRM 职位。
2. 使用已发布职位来源创建职位并录入必填信息。
3. 将职位调整为已关闭并尝试新增候选人。
4. 恢复职位后再次尝试新增候选人。

**预期结果**：

- 未发布职位不能创建。
- 已发布职位创建成功并保留来源凭证。
- 已关闭职位禁止新增候选人，但已有流程不被删除或终止。
- 恢复后允许新增候选人，关闭、恢复和原因均写入审计。

## TS-JOB-002：职位 HR负责人解除与重新指定

**测试目标**：验证职位负责人变更不影响历史责任记录，并确保新负责人具备 HR成员角色。

**前置条件**：准备一个可招聘职位、当前 HR负责人、一个具备 HR成员角色的新负责人和一个无 HR成员角色的用户。

**角色／责任身份**：系统管理员。

**步骤**：

1. 解除当前用户在职位上的 HR负责人绑定。
2. 尝试指定无 HR成员角色的用户为新负责人。
3. 指定具备 HR成员角色的新负责人。
4. 查看职位提醒接收人、历史职位记录和审计记录。

**预期结果**：

- HR成员或系统管理员可以解除和重新指定职位 HR负责人。
- 无 HR成员角色的用户不能被指定为职位 HR负责人。
- 重新指定后，后续待办和长期未推进提醒发送给新负责人。
- 历史创建人、原负责人相关操作人和审计记录不被改写，解除和指定操作均可追溯。

## TS-CAND-001：候选人导入和简历追溯

**测试目标**：验证简历来源、附件安全和导入信息完整性。

**前置条件**：准备合法 PDF、非法文件类型、缺少联系方式的候选人资料。

**角色／责任身份**：HR成员。

**步骤**：

1. 导入完整候选人资料和合法简历。
2. 上传非法类型或内容不匹配的文件。
3. 导入缺少联系方式的候选人。
4. 查看候选人详情和审计记录。

**预期结果**：

- 成功记录来源标识、导入人、导入时间和职位关联。
- 非法附件被拒绝，不产生孤立附件记录。
- 缺少联系方式不能保存。
- 查看和下载简历按权限控制并写入审计。

## TS-CAND-002：重复候选人合并

**测试目标**：验证重复判断、合并确认和历史记录保留。

**前置条件**：准备姓名和联系方式完全相同、仅姓名相同、联系方式相同但姓名不同的候选人。

**角色／责任身份**：HR成员、系统管理员。

**步骤**：

1. 导入三类候选人并触发重复判断。
2. 对强重复执行合并确认。
3. 查看新记录、旧记录、面试记录和合并审计。
4. 使用无权限角色尝试合并。

**预期结果**：

- 完全一致触发强重复提示；仅姓名相同不判重；联系方式相同但姓名不同要求 HR 判断。
- 合并保留合并前后标识、操作者、时间和原因。
- 旧简历、面试安排、面试评价和状态历史均保留，主记录与旧记录的合并关系可追溯。
- 无权限角色不能合并。

## TS-FLOW-001：候选人阶段正向流转

**测试目标**：验证阶段前置条件、角色责任和不可回退规则。

**前置条件**：准备三个身份不同、均待筛选的候选人A、B、C，均无同职位重复活动记录；准备HR、职位用人负责人和实际面试官账号，以及有效面试流程配置。

**角色／责任身份**：HR成员、用人负责人、面试官。

**步骤与预期**：

1. HR分别将A、B、C推荐到初筛，记录推荐人、时间和阶段历史。
2. 用人负责人对A记录待补充：A仍初筛，不能直接创建面试；对B记录通过：D-020检查通过后B进入待邀约；对C记录不通过：C进入淘汰。
3. B尚未记录邀约同意时，HR尝试创建面试：被拒绝，B仍待邀约，无新场次。
4. HR记录B邀约同意后创建合法面试场次：B进入面试中，保存流程快照与实际指派；实际结束及评价门槛另按TS-READY-001、TS-ALIGN-020验证。
5. 尝试将B退回初筛或待筛选：被拒绝；尝试恢复C为活动阶段：被拒绝，终止状态不恢复。
6. 核对允许及拒绝结果、前后阶段、操作者、时间与必要备注审计；A、B、C的流程互不影响。

重复推荐、迟交不通过与CTO不参与分支分别按TS-DUP-020、TS-ALIGN-020、TS-ALIGN-022执行，不用同一候选人连续执行互斥分支。

## TS-FLOW-002：邀约结果和面试前置条件

**测试目标**：验证邀约状态记录、备注要求和创建面试的前置条件。

**前置条件**：候选人处于待邀约，准备 HR成员账号和不同邀约结果。

**角色／责任身份**：HR成员。

**步骤**：

1. 在没有备注的情况下记录邀约中、拒绝或失联。
2. 记录邀约同意但不创建面试。
3. 在邀约状态为同意后创建面试。
4. 查看最近一次邀约状态、操作人、时间和备注。

**预期结果**：

- 邀约状态变更没有备注时不能提交。
- 拒绝或失联可以结束候选人流程，但不能创建面试。
- 只有同意状态允许创建面试。
- 邀约记录和来源不会被伪装成 HRM 自动发送的外部消息。

## TS-INT-001：首次安排选择完整流程并沿用快照

**测试目标**：验证招聘角色和面试职级不属于职位必填字段，并用于模板匹配。

**前置条件**：职位没有招聘角色和面试职级字段；准备两个角色/职级组合和对应模板。

**角色／责任身份**：HR成员、用人负责人。

**步骤**：

1. 创建职位时不填写招聘角色和面试职级。
2. 首次安排选择招聘角色和职级，保存完整流程快照；安排下一轮时沿用并检查不能重新选择流程职级。
3. 修改模板后查看已创建面试。
4. 使用无匹配模板的组合尝试安排面试。

**预期结果**：

- 职位可以在不填写招聘角色和面试职级的情况下创建。
- 首次安排必须选择角色和职级，并匹配完整流程；后续仅选择快照对应轮次，不重新选择职级或独立流程模板。
- 已创建面试保留模板和字段快照，不随模板修改而变化。
- 无匹配模板时不能安排面试，并提示补充配置。

## TS-INT-005：职级流程与多轮评价独立保存

**测试目标**：验证职级决定流程轮次与选人要求，每轮各参与人独立评价，HR沟通不生成面试评价。

**前置条件**：准备 P3-2 与 P4 候选人、对应流程模板、实际面试官指派及 HR成员；P4 安排业务一面、负责人二面、CTO三面和 HR沟通，同一面试官可参与两轮，一轮可有两名面试官。

**角色／责任身份**：HR成员、职位用人负责人、本轮面试官。

**步骤**：

1. 分别匹配 P3-2、P4 的完整流程，查看轮次、选人职责及 HR沟通环节。
2. 尝试移除 P4 的 CTO面；符合一面跳过例外的路径另按 TS-INT-006 验收。
3. 同一候选人的不同轮次分别提交评价，同一人参加两轮分别提交；同轮两人分别提交。
4. 修改一份评价并查看其他轮次评价、原提交人及版本。
5. HR成员记录 HR沟通结果；普通面试官仅凭面试官角色尝试记录 HR沟通结果。
6. 查看候选人详情和工作台待评价，取消某场面试并创建同轮替代场次后查看原评价。

**预期结果**：

- P3-2 为两轮业务面试＋HR沟通；P4 为三轮业务面试＋HR沟通，标准路径含 CTO面。每轮实际参与人分别指派，矩阵姓名不自动授予权限。
- 不允许无记录删除 P4 的 CTO环节；负责人确认不参与例外另按 TS-ALIGN-022 验收；标准四环节按 D-015 可跳过一面，但须保留跳过记录，不能无记录删轮。
- 每份评价能定位到候选人、实际场次、轮次及评价人；同人两轮、同轮两人均分别保存两份评价，不覆盖成单份总评价。
- 修改只作用于选定评价，原评价人、其他轮次评价及模板快照保留。
- HR沟通只保存沟通结果及实际操作人、时间，不生成结构化评价；未有 HR授权的面试官不能凭面试官角色记录 HR沟通结果。
- 详情按轮次、场次、评价人展示；待评价分别跟踪；替代面试保留与原场次及原评价的关联。

## TS-INT-006：一面跳过与二面直接承接

**测试目标**：验证排期／现场冲突下一面跳过、二面实际反馈及 CTO面保留。

**前置条件**：准备 P2、P3-2、P4 候选人与标准流程，一面人员无时间或多个候选人同时到达；当前轮已实际指派面试官，并准备未被指派该轮的用户。

**角色／责任身份**：获授跳轮操作权限的用户、实际二面面试官、CTO面参与人、HR成员。

**步骤**：

1. 授权用户分别标记目标候选人的一面已跳过，填写对应原因，并为原二面指派实际人员。
2. 无跳轮授权用户尝试跳过一面；另尝试在已完成一面的候选人上事后跳过一面。
3. 二面人员实际面试并提交本人二面评价，查看原一面历史及待办。
4. P2、P3-2 在二面终面完成、评价齐全后按现有动作推进；P4 仅二面完成时尝试按终面完成推进，再完成 CTO面并提交该轮评价。
5. 尝试跳过 CTO面，或伪造原一面人员评价；HR记录沟通结果。

**预期结果**：

- 原一面节点标记已跳过，原因、操作者、时间及承接轮次可追溯；二面保留原名称和编号，标准模板不被修改。
- 未授权或已完成一面后的跳过操作被拒绝；已完成一面的评价和历史保留。
- 跳过的一面无评价缺交待办，原已安排场次证据保留且原一面活动待办停止；实际二面评价独立归属于实际参与人，不代原一面人员提交。
- P2、P3-2 以二面为终面，完成且该轮评价齐全后可待决策，并继续 HR沟通结果记录；P4正常路径须 CTO完成且有效责任清单齐全并通过；负责人确认不参与时另按 TS-ALIGN-022 承接前轮。
- 普通面试官不能依一面跳轮例外跳过CTO面；负责人不参与变更另行验收；HR沟通不生成结构化面试评价，不新增待决策阻断。

## TS-DEC-003：前轮缺交与HR沟通不阻断待决策

**测试目标**：验证最终实际轮完成且有效评价齐全通过时自动待决策，前轮缺交和HR沟通未记录不额外阻断。

**前置条件**：P4候选人处于面试中，三轮实际业务面试均已结束，CTO轮由指定完成责任人确认完成；一面至少一份有效通过评价及一份未提交责任，其他已提交评价均为通过；CTO轮只缺最后一份评价，HR沟通尚未记录。

**角色／责任身份**：有权限HR成员、CTO轮最后缺交责任面试官、前轮缺交面试官。

**步骤与预期**：

1. 查看候选人：仍面试中，终面缺评价消息及一面缺交待办分别存在；HR不能点击人工推进到待决策。
2. CTO轮最后缺交责任人提交有效通过评价：有效清单齐全，系统自动激活HR沟通并进入待决策，无需HR推进。
3. HR未填写沟通结果时查看候选人及一面待办：候选人仍待决策，一面缺交任务保留；CTO缺交消息停止。
4. 一面缺交责任人补交通过评价：一面待办完成，保留该轮独立评价，终面评价不被覆盖，候选人仍待决策。
5. 重试提交及刷新：不重复推进、不生成重复待办或决策记录，相关操作审计可追溯。

前轮迟交不通过用独立候选人按TS-ALIGN-020验证；迟交待定按TS-LATE-021另行验证，不把本场景的“通过补交”步骤代替该分支。CTO不参与按TS-ALIGN-022另行验证。

## TS-INT-002：面试安排与变更

**测试目标**：验证面试时间、轮次、面试官和取消规则。

**前置条件**：候选人邀约状态为同意，存在可用面试模板；最后一轮已指定一名终面完成责任面试官。

**角色／责任身份**：HR成员、用人负责人。

**步骤**：

1. HR 创建面试并填写轮次、时间和至少一名面试官。
2. 用人负责人更换面试官。
3. HR 修改面试时间。
4. 由终面面试官点击“完成面试”。
5. 由其他面试官尝试修改已完成面试的结果。
6. 由终面完成责任面试官修改面试结果并填写原因。
7. 分别记录公司取消和候选人取消。

**预期结果**：

- 面试包含候选人、轮次、时间、面试官和创建人。
- 面试官更换不改变候选人阶段。
- 改期后详情和待办显示新时间，并保留变更历史。
- 只有被指定的终面完成责任面试官点击“完成面试”后，面试才进入已完成；其他面试官不能代替完成，计划时间经过不能自动完成。
- 完成后 HR成员或该场面试负责人可修改非评价结果，其他普通面试官不能仅凭参与角色修改；修改前后值、操作者、时间和原因完整记录。
- 公司取消与候选人取消原因分开记录，公司取消不自动重新邀约，但允许基于原邀约创建同一轮次的替代面试。

## TS-INT-004：面试取消、未到场和替代面试

**测试目标**：验证异常面试不会无依据地终止候选人流程，并支持继续安排替代面试。

**状态**：MVP 正式规则。

**前置条件**：候选人处于面试中，邀约状态为同意，存在一场待面试记录和可用面试模板。

**角色／责任身份**：HR成员、面试官。

**步骤**：

1. 将一场面试记录为公司取消并填写原因。
2. 在不重新记录邀约同意的情况下创建同一轮次的替代面试。
3. 将另一场面试记录为候选人取消并填写原因。
4. 将另一场面试记录为候选人未到场并填写确认人和备注。
5. HR 记录候选人愿意继续并创建替代面试。
6. 尝试让系统按时间或事件自动将未到场候选人改为候选人放弃。
7. 由当前招聘环节责任人员点击“候选人放弃”，选择原因=未到场并填写备注。

**预期结果**：

- 公司取消、候选人取消和未到场分别保留结果、原因、操作人和时间。
- 公司取消后可以基于原邀约创建同一轮次的替代面试，候选人保持面试中；替代面试创建新实际场次并关联原面试；必须重新完成和评价，原评价不能满足新场次门槛。
- 候选人取消和未到场可以根据后续沟通创建同一轮次的替代面试，原面试证据保留。
- 系统不能仅因未到场、取消或时间经过自动将候选人置为候选人放弃；转为候选人放弃必须由当前招聘环节责任人员点击按钮并填写原因。
- 公司取消、候选人取消和未到场都可作为候选人放弃原因，原因选项可追溯。
- 点击“候选人放弃”后，候选人进入不可恢复的终止状态；不设置自动时限。
- 替代面试和异常结果均可在候选人时间线和审计中追溯。

2. 全流程无可用实际人员，负责人收到配置警告，结束／跳过／流转被阻止；仅有负责人身份不自动变成面试参与人。
3. 同轮已交评价后换人，评价作者与快照不变，不新建重复缺交任务；未交责任换人时由接任人提交本人评价。
4. 终面必须有有效完成责任人；多人兜底需明确指定一人。有效评价责任清单齐全并通过且终面明确完成后自动进入HR沟通及待决策，终面不能跳过。

## TS-DELETE-018：进入流程后的删除限制

1. 待筛选且无推荐、邀约、面试、评价历史的候选人，HR可软删除；推荐到初筛后、面试中、待决策及进入流程后终止的候选人均不能删除。
2. 职位存在进行中的招聘处理／面试流程，删除被拒绝；无进行中流程时只可软删除，不级联删除关联历史或评价，不接受新候选人。
3. 管理员填写原因恢复职位，原候选人终止状态、评价与快照不变；普通列表隐藏软删除记录。

## TS-DUP-018：同职位判重及跨职位独立

1. 同职位姓名及联系方式一致、无实际面试结束日期，仍提示强重复，不采用录入或计划时间起算一年。
2. 同职位有实际结束时间，以最近一次实际结束起算一年，边界按一周年日期核对；新面试实际结束更新起算依据。
3. 相同身份投递两个不同职位，创建两份独立应聘记录，各自人员、阶段、评价和历史互不影响，不提供跨职位合并。

## TS-MSG-018：终面缺评价站内消息

1. 终面完成但一项有效评价责任未交，向该责任当前接收人立即生成站内消息，候选人仍面试中，HR节点未激活。
2. 按默认周期工作日每日提醒，重复任务同场次同接收人同日仅一条；人员接任更新收件人，已交责任不重复提醒。
3. 补齐后自动进入HR节点及待决策，缺评价消息停止；待决策后的3工作日长期未推进提醒另行计算；取消或终止停止对应任务。
4. 一面缺交不阻断后轮，待办仍保留；终面缺交不因旧文案“未提交不提醒”而被忽略。

## TS-ALIGN-020：通过门槛与不通过自动淘汰

**目标／角色**：当前实际面试官提交反馈，系统自动流转；验证通过继续、不通过终止，指标 M-006。

**前置条件**：准备多名参与人的非终面和终面场次、待定及缺交责任，各用独立候选人验证分支。

**步骤与预期**：

1. 本轮结束但无人交评价：停留等待；一人提交通过且无待定／不通过时，非终面自动进入下一轮待安排，其余缺交待办保留；终面仍须有效责任清单齐全。
2. 有已提交待定时不流转；当前职位负责人依据补充材料修改该评价为通过，保留版本和原因，再判断流转；普通面试官无提交后自行修改权。
3. 任一轮提交有效不通过（含多人已有通过、前轮迟交而后轮已开始）：当前非终止流程直接淘汰，停止后续面试和相关待办／提醒，不要求终面评价补齐，不激活HR沟通。原评价、作者、触发版本、原因、状态审计保留。
4. 修改不通过的历史评价不恢复淘汰流程；重复请求或并发结束仅产生一次有效状态流转，不能继续安排下一轮。

## TS-ALIGN-021：替代场次、换人与建议职级

**目标／角色**：HR创建替代场次、负责人换人、实际面试官评价；验证责任与场次边界，指标 M-003、M-006。

**前置条件**：准备同场次多人终面、已交及缺交责任；另准备取消／未到场原场次与评价历史。

**步骤与预期**：

1. 同场次同轮换人：已交责任复用原评价和作者，未交责任交接，不增加新旧双方重复补评义务；有效责任清单齐全且通过后可自动待决策。
2. 取消／未到场后创建替代场次：视为新实际面试，保留原关联、重新指派、完成和评价；旧场次评价不能解除新终面的缺交阻塞。
3. 评价填写不同建议职级：仅保存建议与依据，原安排职级、完整流程快照及后续轮次不改变；后续安排不重新选职级模板。

## TS-ALIGN-022：CTO不参与与前轮最终评价承接

**目标／角色**：当前职位用人负责人确认CTO不参与，系统引用前轮最终评价并自动到HR；验证权限、快照和门槛，指标 M-006。

**前置条件**：P4／P5流程，准备前一有效实际轮通过齐全、缺评、无前轮和CTO已完成四个分支；负责人、普通面试官及仅HR角色账号。

**步骤与预期**：

1. 普通面试官尝试跳CTO被拒绝；仅HR角色不能执行负责人专属不参与变更。当前职位负责人对具体候选人填写原因确认，保留操作者、时间、原CTO节点、指派及流程变更快照，不重写标准模板。
2. 前一有效实际轮已完成、有明确有效责任人、责任清单齐全且通过：引用原场次、轮次、作者及评价版本作为最终评价，自动待决策并激活HR沟通；不生成虚假CTO评价，未执行CTO待办停止。
3. 前轮缺评则等待、提醒前轮当前缺交责任人，原未执行CTO不重复提醒；补齐通过后仅流转一次。前轮待定不流转，不通过按 TS-ALIGN-020 淘汰。
4. 没有前一有效实际轮、仅有跳过轮／取消场次或旧替代场次评价：警告负责人并阻止流转。CTO已实际完成不能后置确认不参与以抹去历史。CTO正常参加仍需实际完成及有效责任清单齐全且通过。

## TS-DUP-020：初筛推荐时拦截重复活动流程

**目标／角色**：职位用人负责人推荐、HR维护资料与安排；避免同人同职位重复推进，指标M-006、M-007。

**步骤与预期**：

1. 同职位强匹配记录分别为待邀约、面试中、待决策，推荐另一条初筛记录：均被拒绝，当前记录仍初筛，无新邀约、场次或下游待办，原流程不变。
2. 原记录仅待邀约时提示正在招聘处理中，不声称已安排面试；确有安排时提示已安排面试。原记录入口验证当前查看权限。
3. 单条记录排除自身；另一条待筛选或初筛不阻断第一条推荐；两条初筛记录同时推荐，最多一条成功，重试不生成重复业务记录。
4. 仅姓名相同不阻断；联系方式相同但姓名不同提示HR核实；跨职位不阻断；终止记录不触发本条检查，不改变既有历史判重和不可恢复规则。
5. 已有活动记录最近实际面试超过一年仍拦截，不能用历史期限绕过活动流程准入。
6. 创建面试、身份联系方式修改及并发更新不能绕过重复活动流程限制；拒绝结果审计按公共规范，不能通过普通界面覆盖历史或删除已进入流程记录。

## TS-LATE-021：前轮迟交待定不暂停后轮

**依据／目标**：D-021、PRD E.5；验证前轮待定与当前／最终轮门槛分离，指标M-006、M-007。

**前置条件**：三个独立候选人A、B、C，一面多人已有通过反馈、实际结束并合法推进，另一项有效责任未交；A二面待安排，B二面已开始，C最终实际轮已完成且齐全通过、处于待决策。准备当前职位负责人、前轮缺交责任人、当前轮参与人及HR。

**步骤与预期**：

1. 各前轮有效责任人补交待定：A、B、C不回退；详情展示前轮待补充及作者版本，当前职位负责人看到待处理项。
2. HR给A安排下一轮、B当前授权参与人结束本轮并满足本轮通过条件：动作不因前轮待定被拒绝；本轮待定或缺少本轮通过条件时仍按D-019拒绝推进。
3. C由HR完成外部可入职确认及二次确认录用：前轮待定不新增阻断；保留待定历史，录用后活动待办停止，不自动将待定变为通过。
4. 负责人对未终止流程的前轮待定依据补充材料修改为通过：保留原作者、依据及版本，不重复推进；HR尝试修改该评价被拒绝。
5. 独立候选人前轮待定修改为不通过：尚未终止流程按D-019淘汰；已录用、淘汰或放弃的历史评价变化不恢复或切换终止结果。
6. CTO不参与的承接轮仍有待定时：该轮作为最终实际轮，仍不允许进入待决策；不能把“前轮待定不阻断”用于绕过最终承接门槛。

权限、指派、并发及审计遵循公共规范，未授予新角色、提醒频率或终止后补交权。
